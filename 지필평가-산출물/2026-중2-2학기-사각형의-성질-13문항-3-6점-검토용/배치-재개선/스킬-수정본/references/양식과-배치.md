## 문항 수는 어떻게 배치하는가

- 원본에는 ‘단마다 정확히 N문항’ 같은 자동 제한 설정이 없다. **2단·단폭·간격·번호 스타일**이 설정되어 있다.
- 기존 지침은 **그림이 있는 선택형 문항을 왼쪽 단에 3~4개** 배치하는 것을 권한다. 그림마다 기본 폭 68.2mm에서 시작한다. 단 폭·도형 비율·라벨 때문에 잘릴 때만 폭을 조정하고 내보내기 자료에 이유를 남긴다. 모든 문항·모든 단에 3~4개를 강제하거나 문항 수를 맞추려고 폭을 임의로 줄이지 않는다.
- 오른쪽 단은 문항 길이와 서술 공간을 보고 같은 밀도로 균형을 맞춘다. 그림 없는 짧은 문항에는 고정 개수 규칙이 없다.
- 하단에 큰 여백이 남으면 문항 사이 공백부터 늘리지 말고 문항 묶음의 단별 배정과 전체 쪽수를 다시 검토한다. 최종 PDF에서 문항별 시작·끝, 풀이 공간, 단 하단 여유를 측정한다. 단마다 필요한 풀이 공간을 빼고 남은 여유를 문항 사이에 분산하며, 짧은 문항 두 개 사이에 과도한 간격을 만들어 하단만 맞추지 않는다.
- 배치표에 `쪽, 단, 문항 번호, 유형, 그림 유무, 예상 높이`를 기록한다. 본문·조건·선택지를 서로 다른 단이나 쪽에 찢어 놓지 않는다. 필요한 경우 문항 앞에서 단 나눔을 한다.
- 줄 수가 넘치면 선택지 행 스타일, 그림 폭, 문항 사이 간격을 원본 범위에서 먼저 조정한다. 고정 글꼴·본문 크기·쪽 여백을 임의 축소하지 않는다. 최종 쪽수는 실제 렌더 후 표지와 꼬리말에 반영한다.
- 이전 문항의 마지막 선택지 다음에는 **빈 본문 한 줄**을 둔 뒤 다음 자동 번호 문항을 시작한다. `NativeDocument.question()`이 이를 자동으로 넣는다. 이미 `space()`를 호출했거나 단·쪽을 나눈 경우에는 빈 줄을 더 넣지 않는다.

## 자동 번호와 선택지

원본 스타일 이름으로 선택한다. 현재 원본의 ID는 분석 참고값일 뿐 저장 후 번호가 바뀔 수 있다.

| 용도 | 원본 스타일 | 현재 ID |
|---|---|---|
| 선택형 | 선택형문항(번호자동부여) | 3, Ctrl+4 |
| 논술형 | 논술형문항(번호자동부여) | 4 |
| 논술형 소문항 | 논술형문항(분할배점) | 5 |
| 선택지 | 1행 / 2행 / 3행 / 5행 선택지 | 6 / 7 / 8 / 9 |
| 보기 | 지문 박스 안 / <보기>, 다음 상자 안 문장 | 2 / 10 |
| 지문 | 지문 / 바탕글 | 11 / 0 |

선택형의 OUTLINE 번호와 논술형의 NUMBER 번호는 별도 흐름이다. `1.`이나 `【논술형 1】`을 본문에 직접 타이핑하지 않는다. ①~⑤ 선택지 표지는 일반 문자이며, 열 정렬에는 여러 공백 대신 원본 탭을 쓴다.

## 보기 상자

- ㄱ·ㄴ·ㄷ·ㄹ을 문항 본문에 이어 쓰거나 테두리 문자로 둘러싸지 않는다. `NativeDocument.statement_box()`를 호출하여 `assets/statement-box.hwpx`의 실제 표 개체를 끼워 넣는다.
- 실측 상자는 4행 3열, 폭 30613 HWPUNIT(약 108mm)이고 `treatAsChar=1`이다. 위쪽의 `＜보 기＞` 제목을 선 사이에 두고 마지막 3열 병합 셀에 보기 문장을 넣는다.
- 보기 문장에는 **`<보기>, 다음 상자 안 문장`** 스타일을 적용한다. 각 문장은 별도 문단으로 쓰고, 수학 표현은 그 문단 안의 한글 수식 개체로 넣는다.
- 문항 바로 다음 문단에 보기 상자를 넣는다. 문항과 상자 사이에 별도 빈 문단을 두지 않는다. 삽입 조각의 선행 빈 문단이 따라오면 실제로 빈 문단인지 확인한 뒤 그 문단만 제거한다. 보기 문장 기호 앞은 ` ㄱ.`, ` ㄴ.`, ` ㄷ.`, ` ㄹ.`처럼 공백 한 칸으로 시작한다.
- 상자 바깥의 `<보기>` 안내 문구는 예시 설명일 뿐 최종 문항에 중복해서 넣지 않는다. 내용이 길면 표가 늘어나도록 두고 글자 크기나 단 폭을 줄이지 않는다.
- 최종 구조 검사에서 `STATEMENTS_OUTSIDE_BOX`, `STATEMENT_BOX_LAYOUT`, `STATEMENT_BOX_STYLE` 중 하나가 나오면 전달하지 않는다.

## 표 안쪽 여백

검색한 기존 작성 문서에는 모든 표에 동일한 안쪽 여백을 지정하는 지침이 없었다. **원본의 표별 설정은 명확히 존재**하므로 이를 기준으로 한다.

| 원본 표 | 좌우 안쪽 여백 | 위아래 안쪽 여백 |
|---|---|---|
| 결재란·인적사항·안내사항·문제 면 제목 | 283, 약 1mm | 141, 약 0.5mm |
| 표지 시험 제목·시험 시작 안내·저작권·확인 사항 | 510, 약 1.8mm | 141, 약 0.5mm |
| 보기 상자 표 전체 | 0 | 0 |

보기 상자의 본문 병합 셀은 좌우 850(약 3mm), 위 283(약 1mm), 아래 850(약 3mm)의 셀 여백을 사용한다. 위 제목을 만드는 세부 셀의 테두리와 높이는 `assets/statement-box.hwpx`에서 그대로 가져오며 새로 추측하여 만들지 않는다.

안쪽 여백(`inMargin`), 표 바깥 여백(`outMargin`), 셀별 여백(`cellMargin`)을 구분한다. 원본은 검사한 모든 셀의 `hasMargin=0`이므로 셀 속성의 숫자만 보지 말고 표의 안쪽 여백을 따른다. 셀별 여백을 켠 표가 새로 필요하면 그 셀의 유효 여백을 별도로 확인한다.

표를 단순히 같은 mm로 초기화하지 않는다. 기존 표의 행·열·병합·테두리·정렬·안팎 여백을 보존한다. 새 조건·보기 상자는 원본의 해당 스타일을 재사용한다. 내용이 길면 문단을 나누고 필요 높이를 확보하며, 글자를 줄여 억지로 넣지 않는다.
