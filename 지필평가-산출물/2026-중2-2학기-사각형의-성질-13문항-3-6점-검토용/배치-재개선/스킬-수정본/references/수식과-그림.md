# 수식과 그림

## 본문은 본문 수식이다

문항의 한국어 문장·문항 번호·배점·날짜·쪽수는 일반 텍스트/원본 자동 번호로 둔다. 본문·보기·표·답안의 수학적 숫자·문자·연산·관계·단위는 **편집 가능한 한글 수식 개체**로 넣는다.

- 한글의 `EquationCreate`와 `HEqEdit`를 사용하고 `TreatAsChar=1`로 설정한다.
- 원본과 같은 11pt를 사용한다. `EqFontName=HancomEQN`, `BaseUnit=1100`을 기본으로 삼는다. 글자 크기를 사용자가 바꾸라고 한 경우에만 바꾼다.
- 본문 텍스트와 수식을 같은 문단의 글 흐름으로 삽입한다. 문장 전체를 수식, 그림, 별도의 글상자로 만들지 않는다.
- 도형의 점 이름 `A`, `B`, `C`, `D`, `O` 등은 예외적으로 **13pt(`BaseUnit=1300`)**의 한글 수식 개체로 통일한다. 문제 본문·선택지·해설의 수식은 기존 11pt를 유지한다.
- 수식 폭·높이·기준선은 한글 수식 엔진이 계산하도록 둔다. 문자열 길이로 폭을 추정하거나 그림 라벨용 좌표를 지정하지 않는다.
- 수식 더블클릭 시 편집기가 열리고, 본문 앞에 글자를 추가하면 수식도 글줄을 따라 이동하는지 확인한다. 선택할 때 테두리가 보이는 것만으로 그림이라고 판단하지 말고 native 수식 여부와 inline 배치를 확인한다.

## 단위·정체·평행 기호

검증된 변환기: `scripts/equations.py` (`MathGraph/runtime/hancom/equations.py`에서 복사한 구현). 아래 LaTeX를 `to_hwp`에 넣는다. 지원하지 않는 명령은 예외로 중단한다.

| 표현 | 입력 예 |
|---|---|
| 점 이름 | `\mathrm{A}` |
| 선분 이름 | `\bar{\mathrm{AB}}` |
| 변수 | `x`, `y`, `a_n` |
| 길이 단위 | `3\mathrm{cm}` |
| 각 | `\angle\mathrm{ABC}=60^{\circ}` |
| 평행 | `\bar{\mathrm{AB}}\parallel\bar{\mathrm{CD}}` |

- **cm 앞뒤와 평행 기호 앞뒤에 명시적인 공백을 넣지 않는다.** `~`, `\,`, `\quad` 또는 정렬용 공백으로 띄우지 않는다. 변환 스크립트의 명령을 구분하는 문법 공백과 화면에 출력하는 공백을 구별한다.
- 점·선분 이름과 단위는 정체이고 변수는 기울임이다. 한글의 `rm`은 닫는 중괄호 뒤에도 유지되므로 **이전 `rm/it` 상태를 명시적으로 복원**한다. `{rm AB}`만 감싸고 뒤의 `x`가 자동으로 기울어진다고 가정하지 않는다.
- 학교 수학용 비스듬한 평행 기호는 원본 대조 이력이 있는 **U+F005A**를 쓴다. `PARALLEL`이 만드는 수직 `∥`나 두 개의 빗금으로 대체하지 않는다. 새 한글 버전/글꼴에서 모양이 다르면 실제 원본 렌더와 비교한다.
- 분수·지수·첨자 전체의 범위를 묶어 뒤의 덧셈이 분모나 지수로 들어가지 않는지 검사한다. `y=\frac{1}{2}x^2+3`, `a_{n+1}+2`처럼 연속한 항이 있는 식을 함께 점검한다.

## 이해를 돕는 그림과 인쇄 크기

위치·각·선분·구조를 이해하는 데 도움이 되면 MathGraph 그림을 기본적으로 넣는다. 글만으로 풀 수 있다는 이유로 생략하지 않는다. 사용자가 지정한 문항에는 그림을 넣는다. 정답을 직접 드러내는 표시는 제외한다.

- 연결된 프로젝트: `C:/Users/pbj95/Desktop/mathGraph`.
- 그림 계획은 `.agents/skills/mathgraph-drawing/SKILL.md`와 필요한 유형의 참조만 읽는다.
- 입력 경로는 `docs/한글-입력-사용법.md`, `runtime/hancom/hancom.py`와 `model.py`의 검증된 분리 구조를 사용한다. 도형 내보내기를 흉내 낸 그림을 ‘MathGraph로 제작’했다고 하지 않는다.
- 선·곡선은 MathGraph 내보내기 그림으로, 점·길이·변수·단위 라벨은 한글 수식으로 분리한다. 투명 글상자는 그림 라벨에만 쓴다. 점 이름은 인쇄 크기 13pt, 길이·각·대수식 조건은 11pt로 둔다. 화면 배율을 환산한 값으로 5pt까지 축소하지 않는다. 글상자는 기본 10mm이되 긴 수식의 실제 폭보다 작지 않게 늘린다.
- 시험 도형의 꼭짓점·교점·중점은 검은 동그라미 없이 이름만 표시하는 것을 기본으로 한다. 내보내기는 `--point-markers none`을 기본값으로 사용한다. 열린 점·닫힌 점, 강조해야 하는 이동점처럼 점 모양 자체가 수학적 조건인 경우에만 `--point-markers source`를 명시하고 이유를 기록한다.
- 시험 도형의 기본 선 굵기는 `lineWidth=3`이다. GraphA 작업에 별도 굵기가 없으면 `export_mathgraph.mjs`가 3을 채운다.
- HWP 삽입 기본 폭은 **68.2mm**다. 단 폭이나 도형 비율 때문에 잘릴 때만 `--width-mm`로 바꾸고 `--width-reason`에 이유를 기록한다.
- 그림 PNG는 `TreatAsChar=1`, `FlowWithText=1`로 설정하여 **별도 문단에 가운데 정렬**한다. 라벨 글상자는 같은 문단에 고정하고 `FlowWithText=1`로 두어 문단이 이동할 때 그림과 함께 이동하게 한다. 그림을 띄운 뒤 빈 문단으로 높이를 흉내 내지 않는다.
- 좌표축이 필요 없는 도형에는 좌표축을 내보내지 않는다. 무관한 도움점·이름·정답·풀이·과도한 여백을 제거한다.
- 길이 표시 점선은 실선과 같은 실제 선 굵기로 렌더한다. 객체의 lineWidth 값만 같고 내부에서 1px로 그려지는 것은 실패다. export_mathgraph.mjs의 시험지용 내보내기 보정이 구형 앱의 고정 굵기를 보완한다.
- 길이 호는 수직이등분선에 대칭으로 그리고, 최종 인쇄에서 선분과 호 꼭대기 사이 높이 4~7mm를 우선 검토한다. 원시 `curvature` 값만 비교하지 말고 `export_mathgraph.mjs --length-arc-height-mm 5`처럼 실제 인쇄 높이로 지정한다. 같은 문서에서 사용자가 적절하다고 판단한 길이 호가 있으면 그 인쇄 높이와 휘어 보이는 정도를 기준 사례로 삼는다. 짧거나 복잡한 선분은 곡률과 배치를 조절하되 거의 직선처럼 보이지 않게 한다. 라벨 중앙은 실제로 선을 끊고, 두꺼워진 선의 반지름과 여유 공간까지 반영한다. 흰 상자로 선을 가리지 않는다.
- 점 이름 13pt·조건 11pt를 먼저 확정하고 한글 EquationCreate로 실제 폭·높이를 얻는다. native_label_layout.py로 이 실측 사각형과 실제 geometry PNG의 선·점, 다른 라벨 사이에 기본 0.9mm 여유를 확보한다. 화면에서 배치를 마친 뒤 글자만 키우는 순서는 금지한다.
- 점 이름은 내보내기 위치 주변의 제한된 범위에서만 옮긴다. 조건 라벨은 해당 선분의 호 틈이나 해당 각과의 연결을 유지한다. 공간이 없으면 글자를 줄여 통과시키지 말고 GraphA의 구도·여백·각도 호를 수정한다. 한글 실측 배치 기록을 저장하고 최종 PDF에서 배치 결과를 다시 확인한다.
- 각도 **글자**의 크기와 **호**의 반지름을 구분한다. 단순 각 표시는 인쇄 반지름 2~3mm에서 시작하며 `export_mathgraph.mjs --angle-radius-mm 2.2`처럼 실제 mm로 조절한다. 글자를 읽기 쉽게 하려고 호까지 크게 만들지 않는다. 같은 꼭짓점의 여러 호를 구분해야 할 때만 별도 반지름을 쓰고 검토 이유를 남긴다.
- 시험지 내보내기의 기본 호 반지름은 3mm다. 다만 같은 3mm라도 폭이 넓거나 여백이 큰 도형에서는 지나치게 작아 보일 수 있으므로, 최종 PDF를 실제 인쇄 배율로 보고 3~5mm 범위에서 도형별로 조절한다. 한 문서에서 사용자가 적절하다고 판단한 호를 기준 사례로 두되 모든 도형에 같은 수치를 강제하지 않는다. 같은 꼭짓점에서 원래 서로 다르게 지정한 호는 반지름 비를 유지한다. 기존 GraphA의 호 크기를 그대로 보존해야 하는 편집은 `--angle-radius-mm source`를 명시한다. 새 출력의 실제 `printProfile.angleArcs`와 PDF를 대조한다.
- 각도식 라벨은 호의 크기와 별도로 배치한다. 라벨 중심이 해당 각의 내부 이등분선 부근에 있고, 꼭짓점·호와 충분히 가깝게 붙어 다른 각의 값으로 오해되지 않아야 한다. 호만 바꾸는 작업이면 사용자 위치를 보존하지만, 사용자가 위치 이상을 지적했거나 호를 키운 뒤 연결 관계가 흐려졌다면 해당 라벨만 의도적으로 다시 배치하고 다른 라벨은 보존한다.
- 두 대각선의 교점이 반각·직각삼각형 관계를 설명하는 데 쓰이면 실제 intersection 객체 O를 만들고, 그 교점으로 끝나는 BAO·ABO 같은 각 이름을 본문·그림·해설에 일관되게 사용한다. 원문이 다른 점 이름을 지정했으면 임의로 바꾸지 않는다.
- 사용자가 직접 라벨을 옮긴 파일을 주면 이전 생성본을 재사용하지 말고 그 수정본의 위치·앵커·그림 크기를 먼저 비교한다. 호만 고칠 때에는 기존 크롭·그림 비율을 유지하고 글상자를 다시 자동 배치하지 않는다. 라벨이 앞 문단에 앵커를 두거나 그림이 약간 조절된 경우도 있으므로 해당 문항의 문단 전체를 보존한다.
- 글상자 내부 문단의 왼쪽·오른쪽 여백과 들여쓰기를 0으로 초기화한다. 수식 실측 폭에 최소 4mm, 높이에 2mm를 더해 글상자를 만들고 수식 자체의 중심으로 위치를 맞춘다. 외부 충돌이 없어도 내부 문단 여백 때문에 끝 글자가 잘릴 수 있으므로 최종 PDF에서 긴 치수 수식의 마지막 숫자까지 확대 확인한다.
- 라벨 누락도 검사한다. angleDimension/lengthDimension 객체의 존재만으로 통과시키지 않고 customText가 실제 내보내기 labels와 최종 HWPX에 모두 존재해야 한다. ±180도 경계를 지나는 각은 내보내기 시 방향각을 정규화하여 각도 호와 글자가 같은 쪽에 놓이게 한다.
- 각·길이 검산의 expected 값은 원문 조건을 풀어 구한다. 현재 그림의 각도를 측정한 값을 expected에 복사해 불일치를 숨기지 않는다. 도형 모양까지 모든 원래 조건을 동시에 만족하는지 확인한다.
- 문제 본문에 `∠BAC=28°`처럼 각의 값이 명시되어 있으면 MathGraph에 같은 세 점을 참조하는 `angleDimension`을 만들고 각도 호와 `customText: "28°"`를 표시한다. 검수 조건에는 `{"kind":"angle", "points":["B","A","C"], "expected":28, "given":true, "display":"28°", "reason":"문제에 주어진 각 BAC"}`를 기록한다.
- `AO=3x+5`처럼 특정 선분의 길이·대수식이 주어지면 해당 선분을 참조하는 `lengthDimension`을 만들고 `customText: "3x+5"`를 가까이 표시한다. 검수 조건에는 `{"kind":"segment_label", "points":["A","O"], "given":true, "display":"3x+5", "reason":"문제에 주어진 선분 AO"}`를 기록한다.
- 주어진 조건과 다른 임의 길이·평행·직각·각도 호를 넣어 새 조건처럼 보이게 하지 않는다. 대표 좌표를 쓴 경우 조건·비퇴화·점의 위치·교점·길이비를 계산하여 검증한다. `geometry_review.py`가 기본 폭·선 굵기와 `given/display`에 대응하는 각도·길이 치수 개체도 확인한다.
- 검증 기록에 `MathGraph 생성/내보내기 근거`, 프로젝트 파일, 본문 수식과 그림 라벨의 구분을 남긴다. 그림 없는 시험에는 이 경로를 실행하지 않는다.

각의 꼭짓점 문자도 정체로 쓴다. 세부 판단표와 올바른 한글 스크립트는 [rm/it 판단과 예시](rm-it-판단과-예시.md)를 반드시 따른다.
