# 한글 작성·실행·전달 검사

## 공통 작성 도구

원안지에 일반 시험 문항을 넣을 때는 `scripts/native_author.py`의 `NativeDocument`를 기본으로 쓴다. 이전 시험지의 임시 제작 코드를 복사하여 한글 자동화·스타일·그림 라벨 부분을 다시 만들지 않는다. 다른 양식이나 이 도구가 지원하지 않는 편집은 공식 HwpAutomation 참조를 확인한 뒤 최소 범위로 확장한다.

필요 환경: Windows 한글, Python의 `pywin32`, `lxml`, `pypdfium2`, `numpy`, `Pillow`, MathGraph의 `runtime/hancom`. 기본 MathGraph 경로는 `C:/Users/pbj95/Desktop/mathGraph`이며 다른 체크아웃을 쓰려면 `mathgraph_root`를 지정한다. 앱 코드와 환경 변수는 변경하지 않는다.

```python
import sys, json
from pathlib import Path
skill = Path(r'C:/Users/pbj95/.codex/skills/pbj-exam-hwpx')
sys.path.insert(0, str(skill / 'scripts'))
from exam_tools import prepare
from native_author import NativeDocument

# 실제 시험정보와 문항 데이터를 먼저 확정한다. 출력 폴더는 새로 만든다.
prepare('시험정보.json', '준비본.hwpx')
document = NativeDocument('준비본.hwpx')
with document as doc:
    doc.body_start()
    doc.question([('text', '다음 식의 값은? '), ('eq', '2+3')], points=4)
    doc.choices([[('eq', str(n))] for n in [1,2,3,4,5]], rows=(5,))
    doc.question([('text', '항상 옳은 것만 고르시오.')], points=4)
    doc.statement_box([
        [('text', '첫째 문장')],
        [('text', '둘째 문장')],
        [('text', '셋째 문장')],
    ])
    doc.choices([[('text', label)] for label in ['ㄱ','ㄴ','ㄷ','ㄱ, ㄴ','ㄱ, ㄴ, ㄷ']], rows=(3,2))
    # 필요한 위치에서 doc.new_column(), doc.new_page()를 사용한다.
    doc.save('학생용.hwpx')
print(document.session.shutdown)
```

위는 API 사용 예시다. **준비본.hwpx와 최종 학생용.hwpx는 서로 다른 경로**다. `prepare`로 만든 경로에 다시 `save`하면 덮어쓰기를 막기 위해 중단한다. 시험정보의 문항 수·배점은 실제 작성 내용과 맞아야 한다. 제작 코드는 기존 최종 폴더를 덮어쓰지 않는 새 출력 경로를 요구하도록 만든다.

- 본문 조각은 `('text','한국어 문장')`, `('eq', r'\angle\mathrm{ABC}=(3x+10)^{\circ}')`로 나눈다. 숫자·영문·수학 기호가 본문 텍스트 조각에 들어가면 중단한다.
- `question(parts, points, kind='mc' 또는 'essay')`는 원본 스타일을 이름으로 찾아 자동 번호와 배점을 적용한다.
- `choices(choices, rows=(5,))`: 한 문단에 다섯 보기와 탭. 두 행은 `(3,2)` 또는 `(2,3)`, 세 행은 `(2,2,1)`, 다섯 행은 `(1,1,1,1,1)`처럼 배정한다. 실제 단 폭에서 넘치면 행 구조를 바꾸고 다시 렌더한다.
- `statement_box(statements)`: ㄱ·ㄴ·ㄷ·ㄹ 문장을 `assets/statement-box.hwpx`의 실제 보기 상자에 넣는다. 각 문장은 text/eq 조각 목록이다. 문항 본문에 ㄱ·ㄴ·ㄷ을 한 문장처럼 이어 쓰지 않는다.
- `question(...)`: 두 번째 문항부터 앞 문항의 선택지 뒤에 빈 본문 한 줄을 자동으로 확보한다. `space()`, 단 나눔, 쪽 나눔을 이미 적용한 경우에는 같은 여백을 더하지 않는다.
- `space(lines)`는 빈 풀이 공간이다. 긴 밑줄 문자열로 답란을 만들지 않는다. 밑줄이 다음 줄로 접히는 문제를 피한다. 줄이 꼭 필요하면 문단 테두리 같은 실제 서식으로 별도 구현·검증한다.
- `diagram(export)`에는 MathGraph가 내보낸 PNG·폭·비율·라벨 위치 데이터가 들어 있는 JSON을 준다. 그림 아래에 A,B,C를 나열하는 방식으로 대체하지 않는다. 그림은 `TreatAsChar=1`인 별도 가운데 정렬 문단에 들어가고, 라벨 글상자는 같은 문단을 따라 이동한다. 점 이름 수식은 13pt다. 예: `doc.diagram(json.loads(Path('MathGraph/내보내기.json').read_text(encoding='utf8')))`.
- 교사용은 `NativeDocument()`로 별도 문서를 만들고 `line(parts)`를 사용한다. 제목·문항 번호·배점 같은 관리 정보만 `metadata=True`로 허용한다. 수학 내용 검사를 피하려고 모든 본문에 이 옵션을 붙이지 않는다.
- 저장 후 한글 종료 결과 `session.shutdown`도 보관한다. 검증용 새 한글 인스턴스는 `OwnedHwp`가 직렬 실행하고 자신이 연 문서만 닫는다. `Visibility`, `Show`, `ShowDialog`를 종료 단계에서 호출하지 않는다. 사용자 문서가 끼어들면 전체 종료를 하지 않고 중단한다.

교사용의 기본 흐름은 다음과 같다. `prepare`와 `body_start`를 사용하지 않는다.

```python
with NativeDocument() as doc:
    doc.line([('text', '정답 및 해설')])
    doc.line([('text', '선택형 1번 [4점]')], metadata=True)
    doc.line([('text', '정답은 ⑤이다. '), ('eq', '2+3=5')])
    doc.style()
    doc.parts([('text', '관계를 식으로 나타냄')])
    doc.parts([('text', ' [4점]: ')], metadata=True)
    doc.parts([('eq', r'\angle\mathrm{A}=60^{\circ}')])
    doc.paragraph()
    doc.save('교사용.hwpx')
```

채점 기준도 text/eq 조각으로 저장한다. 관리용 점수만 metadata 조각으로 넣고, 기준 문장의 x·AB·각·계산식은 수식 조각으로 둔다. '수학 표현이 섞인 문자열 전체'에 metadata=True를 붙여 검사를 우회하지 않는다.

한글 실행 전 사전점검은 본문과 보기뿐 아니라 **실제로 출력할 채점 기준 제목, 답만 쓴 경우의 설명, 해설의 모든 조각**을 포함한다. 예를 들어 ‘방정식을 세우고 x를 구함’의 x도 수식 조각이어야 한다. 기준 제목을 ‘미지수의 값을 구함’으로 쓰고 바로 뒤에서 실제 수식으로 설명할 수도 있다.

## MathGraph 내보내기

GraphA 데이터에 실제 도형과 필요한 라벨을 먼저 만든 다음, 제공된 `scripts/export_mathgraph.mjs`로 내보내는 것을 기본으로 한다. Node와 해당 MathGraph 프로젝트의 Playwright, 설치된 Edge를 사용한다.

```text
node scripts/export_mathgraph.mjs --input MathGraph/도형.grapha.json --output MathGraph/내보내기.json
```

기본값은 `--width-mm 68.2`, `lineWidth=3`이다. 단 폭·비율 때문에 폭을 바꿔야 할 때만 `--width-mm 72 --width-reason "세로로 긴 도형의 라벨 잘림 방지"`처럼 이유를 함께 기록한다.

도구는 앱의 schemaValidator·patchApplier와 `captureHwpDiagram`을 호출해 PNG·크롭 비율·라벨 위치를 함께 계산한다. 결과의 preview.png를 보고 점 이름이 제자리에 있는지 확인한 뒤 JSON 전체를 `doc.diagram`에 준다. 유한한 점·원 범위에 화면을 맞추며, 범위가 없는 그래프는 명시적 `--scale`이 필요하다. 이 기본 도구는 좌표축 없는 도형용이다. 축이 필요한 그래프는 앱의 `captureHwpDiagram`을 `includeAxes:true`로 호출하고 별도로 검증한다.

원시 `mainCanvas.toDataURL()`에 화면 비율 2/3이나 추측한 라벨 좌표를 붙이지 않는다. 점을 숨길 때 이름도 사라지는지 확인한다. `showLabel:true`인 실제 점이나 필요한 TextLabel을 만든 뒤 내보낸다. 라벨 수가 0인데 문항이 A·B·O 등을 참조하면 내보내기가 완성된 것이 아니다.

## 실제 한글 실행 확인

두 최종 HWPX에 `hwpx` 스킬의 `fill_hwpx.py check --strict`와 XML 검사를 실행한다. 이어서 아래 명령을 실행한다. 명령마다 종료 코드와 결과 JSON을 확인하며, 여러 명령을 세미콜론으로 연결한 마지막 종료 코드만 보고 모두 성공했다고 판단하지 않는다.

```text
python scripts/native_verify.py 학생용.hwpx --pdf 학생용.pdf --receipt 학생용-한글검증.json
python scripts/native_verify.py 교사용.hwpx --pdf 교사용.pdf --receipt 교사용-한글검증.json
```

이 도구는 최종 HWPX를 열어 PDF로 출력하고, 복사본에서 수식 수정·본문 흐름과 모든 수식의 실제 크기를 확인한다. 마지막에는 소유 문서 → 한글 종료 → 해당 창과 새로 만든 프로세스의 종료를 확인한다. 새 실행의 PDF와 영수증 경로를 지정한다. 원본 HWPX는 저장하지 않는다. 종료 확인을 포함한 새 영수증은 `schema: 2`이다.

오류 뒤에 파일이 존재해도 성공으로 판단하지 않는다. 실제 오류와 프로세스 종료 상태를 확인한 뒤 원인을 고쳐 새 경로에서 재실행한다. 과거 팝업의 정확한 원인을 출력 오류만으로 단정하지 않는다. 창을 닫는 중 발생한 Visibility 관련 오류는 시험지의 수학적 정확성과 별개의 검사 대상이다.

샌드박스에서 공통 잠금 파일 접근이나 한글 COM 연결이 거부되면 오류가 발생한 단계를 확인한다. 권한이 필요한 실제 생성·검증 명령은 환경의 승인 절차를 이용한다. 잠금 파일 삭제·잠금 경로 변경으로 직렬화를 우회하지 않는다. Windows 출력의 한글·평행 기호가 깨지거나 UnicodeEncodeError가 발생하면 Python을 `-X utf8`로 실행한다.

## 검수 틀 만들기

```text
python scripts/review_scaffold.py --student 학생용.hwpx --teacher 교사용.hwpx --student-pdf 학생용.pdf --teacher-pdf 교사용.pdf --metadata 시험정보.json --output 검수
```

틀 생성은 검수 완료가 아니다. 모든 시각 검사 값은 false, 수학 판정은 미입력, 독립 판정은 PENDING이다. [문항별 검산·독립 검토](문항별-검산과-독립검토.md)를 수행한 뒤 각각 채운다.

`학생용-검수.json`과 `교사용-검수.json`에는 최종 네 파일, 메타데이터, 문항별 검산, 별도 검토 결과의 경로가 연결된다. 상대 경로는 **검수 JSON이 있는 폴더**를 기준으로 해석한다.

- `pages`: 모든 쪽에서 잘림·겹침·양식·풀이 공간을 직접 확인한 결과와 관찰 내용
- `questions`: 모든 문항의 실제 쪽과 단. PDF에서 유일하게 찾을 수 있는 번호·문구를 `text`에 넣는다. 선택형은 마지막 보기 `⑤`를 포함한 실제 PDF 발췌문을 `end_text`에도 넣는다. 번호만으로 중복되면 앞선 보기까지 포함한 유일한 문구를 사용한다. 검사기는 발췌문 안 마지막 `⑤`의 위치가 문항 시작과 같은 쪽·단인지 확인한다. 문항 시작만 같은 위치에 있고 그림이나 선택지가 다른 단으로 넘어간 파일은 완성본이 아니다. 수식 글리프 때문에 검색이 안 되면 실제 PDF 추출 결과를 확인한다.
- `diagrams`: 각 그림의 최상위 문단(`Contents/section0.xml:N`), MathGraph 내보내기 JSON 경로 `export`, 그 파일의 `export_sha256`. 그림의 비율과 라벨 수·수식·위치를 대조한다.
- 라벨 위치는 화면 내보내기 좌표와 완전히 일치해야 하는 값이 아니다. 한글의 실제 수식 크기로 재배치한 뒤 `verify_native_labels.py`로 저장된 HWPX의 실제 수식 영역과 도형 PNG·다른 라벨의 충돌을 검사한다. 점 이름 13pt·조건 11pt, 원래 위치와의 제한된 이동 범위도 확인한다. 실행 예: `python scripts/verify_native_labels.py 학생용.hwpx --exports 그림1.json 그림2.json --output 실측-충돌-검사.json`. 이 검사는 `delivery_check.py`에도 연결되어 있으며 PDF 확대 확인을 대신하지 않는다.
- 사용자가 직접 고친 위치를 보존하는 편집은 `user_layout_preservation: {"source":"사용자수정본.hwpx","source_sha256":"실제해시"}`를 검수 JSON에 명시한다. `preserved_diagram_review.py`가 기존 라벨의 위치·크기·앵커 역할을 원본과 직접 대조하고, 새 라벨의 충돌·실제 인쇄 비율의 도형 조건·그림 바이너리를 검사한다. 기존 자동 배치의 0.9mm 여유 기준을 이유로 사용자 위치를 다시 옮기지 않는다. 사용자가 특정 라벨의 위치 수정을 요청한 경우에만 `allowed_label_changes`에 `question`, `script`, 최종 `after_pos`, 구체적인 `reason`을 적는다. 검수기는 선언한 라벨의 위치만 달라졌는지, 선언 위치와 일치하는지, 새 위치에서 선·점·다른 라벨과 충돌하지 않는지를 검사하며 사용하지 않은 예외 선언도 실패시킨다. 이것은 최종 PDF 확인을 대신하지 않는다. 사용자가 수정본을 제공하지 않은 신규 제작에는 이 모드를 쓰지 않는다.
- 각 `diagrams` 항목의 `conditions`에는 문항의 실제 도형 조건을 기록한다. `geometry_review.py`가 해시로 연결된 내보내기의 `project` 좌표에서 각도·길이의 비·평행·중점을 확인한다. ‘이등변이다’만 확인하고 주어진 외각을 빠뜨리거나, ‘평행사변형이다’만 확인하고 대수식에서 얻는 각과 변의 비를 빠뜨리지 않는다. 원문 조건 전체와 검사 조건의 대응은 독립 검토자가 확인한다.
- `content`: 직접 완료한 검수 항목과 구체적 메모. 문항별 검산과 독립 검토를 대신하지 않는다.

도형 조건 예시:

```json
"conditions": [
  {"kind":"angle", "points":["A","C","D"], "expected":124, "given":true, "display":"124°", "reason":"문항에 주어진 외각 ACD"},
  {"kind":"segment_label", "points":["A","O"], "given":true, "display":"3x+5", "reason":"문항에 주어진 선분 AO"},
  {"kind":"length_ratio", "points":["A","B","A","C"], "expected":1, "reason":"주어진 두 변 AB와 AC의 길이가 같음"},
  {"kind":"angle", "points":["B","C","D"], "expected":180, "reason":"BC의 연장선 위에 D가 있음"}
]
```

`angle`은 가운데 점의 각(0~180도), `length_ratio`는 첫 두 점의 거리/뒤 두 점의 거리다. `segment_label`은 특정 선분 가까이에 문제에 주어진 길이·대수식을 표시했는지 확인한다. `parallel`은 네 점으로 두 선분을 지정하고, `midpoint`는 `[끝점, 중점, 끝점]`으로 지정한다. 문제에 직접 주어진 각·선분 표시는 `given:true`와 `display`를 반드시 쓴다. 모든 조건에는 원문과 연결한 `reason`이 필요하다. 좌표의 단위를 cm로 가정하지 않고 길이의 비를 비교한다. 각도 허용 오차는 0.1도이며 작은 좌표 반올림만 허용한다. 현재 자동 검사는 자유점과 두 직선·선분의 교점을 지원한다. 그 밖의 도형을 근거 없이 자유점으로 바꿔 통과시키지 말고 필요한 계산 경로를 구현·검증하거나 검증 미완료를 밝힌다.

## 최종 전달 검사

실제 독립 검토 결과를 연결한 뒤 두 파일을 각각 검사한다.

```text
python scripts/delivery_check.py 학생용.hwpx --pdf 학생용.pdf --native 학생용-한글검증.json --review 검수/학생용-검수.json --mc 8 --essay 2 --points 100 --diagram-paragraph Contents/section0.xml:22
python scripts/delivery_check.py 교사용.hwpx --pdf 교사용.pdf --native 교사용-한글검증.json --review 검수/교사용-검수.json --role teacher
```

문항 수·배점·그림 문단은 실제 값으로 바꾼다. 그림이 없으면 `--diagram-paragraph`를 생략한다. 그림 문단을 선언하는 것만으로 라벨 검사를 면제하지 않는다.

이 검사는 이전의 단순 true 체크 대신 다음 자료를 연결한다.

1. 최종 HWPX/PDF 및 실제 한글 실행·종료
2. 표지의 실제 고정 문구와 시험정보·쪽수
3. 선택지 실제 행 구조와 모든 문항의 PDF 위치
4. MathGraph 내보내기와 한글 라벨 위치
5. 보기별 판정, 논술형 채점 기준, 원문 값 대입 계산
6. 별도 검토자의 모든 문항·전체 쪽 검토 및 미해결 결함 여부

`REVIEWED_WITH_INDEPENDENT_EVIDENCE`도 모든 미래 오류를 증명해 없애는 판정은 아니다. 별도 보고서가 틀릴 수 있으므로 모순이나 반례가 있으면 재검토한다. 파일을 수정하면 영향을 받는 실제 검증과 독립 확인을 다시 수행하고, 해시만 바꿔 이전 PASS를 재사용하지 않는다.
