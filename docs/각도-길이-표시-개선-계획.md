# 각도·길이 표시 개선

## 요구사항(PRD)

- 각도 숫자는 해당 호의 이등분선 쪽에 정렬하고, 밖으로 옮기면 곡선 지시 화살표로 해당 호를 가리킨다. 가까이 놓인 숫자에는 불필요한 화살표를 붙이지 않는다.
- 화살표는 자동·항상·숨김을 선택하고 곡선을 직접 드래그하여 휘어짐을 조절한다. 숫자·호·도형이 움직이면 연결점도 따라간다.
- 길이 숫자는 점선 호 위에 두고, 숫자를 움직일 때 점선도 숫자를 지나도록 조절한다. 점선 간격을 넓히고 사용자 조절 항목을 제공한다.
- 새 수동 도형의 점 이름은 도형 바깥에 배치한다. 저장된 교사 위치는 유지하며 필요할 때 명시적으로 표시 정렬을 실행한다.
- 직각은 반올림 수치로 판정하지 않는다. 호·직각·숫자·화살표의 선택과 드래그, 실행 취소, 저장, 내보내기를 일치시킨다.
- AI가 곡선 지시 화살표의 적용 상황·JSON 속성·예외를 실제 프롬프트와 런타임 기능 설명에서 읽도록 연결한다.

## 구현 계획

1. Dimension 객체에 공유 곡선 기하 계산을 두고 각도 지시선 모드·곡률과 길이 라벨의 호 위 위치·점선 간격을 저장한다.
2. 실제 표시 위치 기반 클릭 판정, 선택된 치수 우선 처리, 각도 호 반지름을 포함한 히스토리를 연결한다.
3. 속성 패널에서 화살표 모드·휘어짐·점선 간격·표시 정렬을 편집한다. 기본 위치와 사용자 수동 위치를 구분한다.
4. AI 구조화 출력·검증·패치·장면 변환·런타임 매뉴얼에 신규 필드를 연결하고 사용 지침과 예시를 문서화한다.
5. 회귀 검사, 전체 기존 검사·정적 빌드, 실제 브라우저의 생성·드래그·저장·내보내기 및 혼잡한 도형을 확인한다.

## 범위와 제약

- 각도에 붙는 곡선 지시 화살표를 일반 도형에서 재사용한다. 자유로운 장식용 곡선 도구나 외부 AI 서비스 변경은 범위 밖이다.
- 기존 사용자 파일·점 좌표·수동 라벨 오프셋은 덮어쓰지 않는다. 구형 프로젝트는 기존 위치를 유지하도록 불러온다.
- 사용 스킬: mathgraph-drawing, pbj-ui-copy, frontend-testing-debugging, routing-personal-playbooks. 큰 화면 개편은 아니므로 이미지 시안은 만들지 않는다.
- 최초 구현 당시 쓰기 허용 범위는 원본 프로젝트였고 .git과 .agents는 읽기 전용이었다. 후속 지침 정리에서 권한이 해제되어 기존 코드 전용 worktree로 변경을 옮기고 스킬 원본·runtime 지침을 동기화했다. 운영 배포는 이번 범위에 포함하지 않는다.

## 완료 기준

각도 숫자를 밖으로 옮겨도 소속이 명확하고 화살표 끝과 호 사이에 작은 여백이 남는다. 길이 숫자는 호의 틈에 놓인다. 세부 조절이 저장·불러오기와 undo/redo를 거쳐 유지된다. 실제 검사 결과와 미검증 항목을 진행 기록에 구분한다.

## 2026-10-01 표시 피드백 반영

- 목표: 검수한 40° 삼각형의 불필요한 화살표, 작은 숫자, 불필요한 소수점과 두 줄 같음 표식을 고친다. 기존 좌표·길이·각·점 이름 위치는 유지한다.
- 생성 기준: 읽을 수 있는 글자 상자 전체가 내각 안에 들어가면 화살표를 생략한다. 들어가지 못하면 해당 삼각형/다각형의 실제 바깥에 글자를 두고 지시선을 연결한다. 교사 수동 배치를 자동 이동하지 않는다.
- 화살표: 목표 호와 연결 관계는 유지하되 끝을 약 7px 띄우고, 화살촉은 선 굵기에 비례해 더 크게 그린다. 호 선택·화살표 곡률 드래그를 구분한다.
- 숫자: 자동 값과 단순 수치 라벨의 불필요한 소수 0을 없앤다. 식·변수·단위 의미는 보존한다. 새 치수의 기본 크기는 24px로 올리고, 이번 예시는 치수 28px·점 이름 34px로 검수한다.
- 같은 각: 이번 한 묶음은 한 줄씩 쓴다. 독립인 여러 묶음은 표식 수로 계속 구별한다.
- 검증: 단위 회귀 → 실제 앱의 내부/외부 배치·화살표 간격·숫자·undo/redo·저장 왕복 → 기존 100종과 복합 45종 렌더를 실행한다. 외부 모델 실호출과 HWP 인쇄는 별도 미검증으로 남긴다.
- 관리 복구: 누락된 ai-work 실행 파일을 원본 CLI에 연결하고 기존 기준 브랜치를 별도 checkout에서 열었다. 임시 작업을 등록·세션 연결한 뒤 clean 커밋을 영구 worktree로 펼쳤다. 원본 폴더·기존 worktree·main·운영 배포는 변경하지 않았다.
- 상태: 구현 및 로컬 검수 완료. 자동/단순 수치 라벨의 소수 0 제거, 새 치수 24px, 내각 글자 상자와 실제 도형 경계 검사, 외부 배치, 화살표 끝 여백과 굵기별 화살촉을 연결했다. 이번 40° 시안은 치수 28px·점 이름 34px·같은 각 한 줄이며 좌표·점 이름 위치는 유지됐다. 최종 659개 검사·정적 빌드, 실제 앱 표시 수정 두 기준점·외부 표시·저장 픽셀 왕복, 기존 145종과 네 고의 오류 탐지가 통과했다. 코드 커밋 d5dc8dc의 작업 브랜치 전송·자동 Preview Ready를 확인했다. 외부 API·한글 인쇄·운영 반영은 하지 않았다. 사용 스킬은 solo-ai-workbench, routing-personal-playbooks, mathgraph-drawing, skill-creator, frontend-testing-debugging이다.

## 진행 상태

### 2026-10-02 추가 그림에서 발견한 지시선 누락

- 재현: 넓은 각도식이 도형 밖에 놓여도 곡선 제어점이 글자 상자 안에 있으면 지시선을 그리지 않았다. 화살표가 필요한 외부 글자의 연결이 빠지는 경우다.
- 수정 범위: 글자 상자에서 실제로 빠져나오는 시작점을 구하고 짧은 곡선의 휘어짐을 제한한다. 자동 외부 배치는 연결 가능한 후보만 선택한다. 좌표·각·길이·기존 수동 위치와 표시 모드는 바꾸지 않는다.
- 간격 보완: 호 중앙 연결점까지의 거리만 재지 않고 실제 원호/직각 선과의 최단 거리를 사용한다. 새 외부 배치는 화살촉에 가려 선이 너무 짧아지는 후보도 피한다. 기존 수동 위치는 유지한다.
- 검증: 넓은 글자 상자의 누락을 단위 검사로 재현한 뒤 수정한다. 서로 다른 새 그림 6개, 기존 145종, 실제 앱 내외부 표시·저장과 최종 관리 검증을 확인한다. 외부 모델 호출과 운영 반영은 범위 밖이다.
- 결과: 재현 테스트의 실패→통과를 확인했다. 새 6종의 조건·표시·음영/끝점 픽셀·앱 생성·undo/redo·저장 PNG 왕복이 통과했다. 실제 원호와의 최단 간격은 7px이며, 기존 145종과 네 고의 오류 탐지·앱 원샷도 통과했다. 전체 661개 검사와 정적 빌드가 통과했고 사용자 원본 파일과 운영은 변경하지 않았다.

- 구현 전: 이전 점검에서 지시 화살표 부재, 점 이름의 클릭 가로채기, 직각 클릭 영역 불일치, 반올림 직각 오판정을 재현했다. 추가로 각도 호 반지름이 드래그 히스토리에서 빠지는 코드 경로를 확인했다.
- 구현: 각도에 붙는 곡선 화살표의 자동·항상·숨김, 직접 휘어짐 조절, 길이 숫자의 호 부착·점선 간격, 새 수동 도형의 점 이름 배치, 명시적 표시 정렬을 연결했다. 구형 위치 보존·저장·undo/redo·내보내기를 처리했다.
- AI: 일반 생성·사진 해석의 구조화 출력, 장면 변환, 검증, 패치, 생성 후 배치에 신규 필드를 연결했다. `AnnotationGuide.js`를 실제 프롬프트에 포함하고 사용법 문서를 프로젝트 진입 지침에 연결했다. 보호된 스킬 원본은 변경하지 않았다.
- 검증: MathGraph 전용 검사 490건과 정적 빌드 통과. 인앱 브라우저에서 실제 숫자·곡선·직각 드래그와 undo/redo, 화살표 모드, 반올림, 저장 PNG 왕복을 확인했다. 기존 100종·복합 45종의 실제 렌더·조건·저장 검사는 최종 오류 0건이다. 이 145종은 합성 회귀 입력이며 교사 승인이나 임의 문항 성공률이 아니다.
- 제한: 기본 `npm run vercel-build`는 미추적 HWPX 별도 저장소의 bun·브라우저 검사까지 검색하여 실패했다. 앱 전용 전체 검사와 정적 빌드를 분리 실행했고 검증 조건이나 기본 명령은 약화하지 않았다. Playwright 새 프로세스는 EPERM으로 실행되지 않아 허용된 인앱 브라우저 개발 도구로 검사했다. 모바일 터치·외부 AI 실호출·HWP 인쇄는 미검증이다. 현재 .git 읽기 전용 권한으로 커밋·푸시·배포는 미실시다.
- 후속 정리: 코드 전용 worktree에서 기존 의존성을 연결한 뒤 변경하지 않은 `npm run vercel-build`가 490건 검사와 함께 통과했다. 스킬 형식 검사, 신규 지시선 검색어의 기능 선택, 20° 예제의 스키마·실제 각을 확인했다. 구현·문서·검사 소스만 작업 브랜치에 커밋·푸시하며 HWPX·교사 자료·렌더 산출물은 제외한다.
