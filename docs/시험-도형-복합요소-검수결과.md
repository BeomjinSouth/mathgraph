## 반복 중 발견해 고친 문제

1. 첫 그림에서는 함수에 좌표축을 표시하지 않아 음영과 x축의 관계를 읽기 어려웠다. 축을 넣자 30개 개발 사례 중 12개에서 함수 이름이 축과 겹쳤다. 자동 배치가 축을 선으로 보지 않던 원인을 고쳤다.
2. 높이가 큰 지수함수 영역이 화면 위에서 잘려도 최초 검사는 통과했다. 영역 전체가 캔버스 안에 있어야 한다는 검사를 추가하고, 함수별 배율을 조정했다. 함수 이름은 자신의 곡선을 따라 후보 위치를 찾아 다른 곡선과 축을 피한다.
3. 두 함수가 구간 끝에서 만나지 않는 경우 음영의 수직 경계가 흐릿했다. `functionRegion`에서 양 끝 경계선을 그리도록 했다.
4. 분모의 영점이 샘플 지점과 정확히 일치하지 않으면 유리함수 음영이 극점 양쪽을 잘못 이어 그릴 수 있었다. 부호가 큰 크기로 갑자기 바뀌거나 값이 좁은 구간에서 급격히 치솟는 경우를 거부하고 회귀 검사를 추가했다.
5. 새 영역을 AI 엄격한 출력 형식, 장면 추출의 짧은 `refs`·`numbers` 형식, 객체 참조 검사, 프로젝트 저장·복원, SVG 출력에 연결했다. [OpenAI 구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 필수 속성·`additionalProperties:false` 조건도 확인했다.

- 이 45종은 재현 가능한 GraphA를 만들어 앱의 생성·배치·출력 경로로 보낸 검사다. 별도로 함수식과 수치 x구간이 명시된 한국어 넓이 요청, `ABC`의 두 등변·두 밑각·밑변 길이·꼭지각, `ABCD` 평행사변형의 두 쌍의 대변·맞은각·밑변 길이·내각을 로컬 단일 요청으로 검사했다. 조건이 더 있거나 수치가 자동 배치 범위를 넘으면 맨몸 도형을 만들지 않고 오류로 끝난다. 범위를 쓰지 않은 함수 넓이 요청과 극점이 든 구간도 오류로 끝난다. 로컬에 OpenAI/Gemini API 키가 없어 이 문법 밖의 임의 문항을 실제 모델에 1회 보내는 성공률은 측정하지 못했다.
- 삼각기둥의 높이 치수는 3차원 길이를 비스듬한 2차원 투영에 표기한 것이다. 투영된 선분 길이를 6으로 계산하는 방식이 아니다. 사각뿔은 화면상 수직 높이를 정확히 표시하는 시험 도식이며 3D 실측 모델은 아니다. 원기둥은 반지름·높이가 모두 명시된 형식만 검사했다. 접선은 대상 함수와 접점 x좌표가 명시된 경우에만 함수 영역과 함께 만든다. 모델 출력의 조건 누락 검사도 특정 명시 형식에 대한 방어이며, 임의 문항의 의미를 전부 판정하지는 못한다.
- 2026-09-24 후속 검사에서는 전체 45종·100종이 다시 오류 0건이었다. 앱에서 함수 원샷 5개, 평면도형 2개, 입체도형 4개를 통과했고, 네 입체 프로젝트의 레이아웃 검사도 오류·경고 0건이었다. 테스트 442건과 정적 빌드가 통과했다. 모델 출력에서 표식·연결 대상·독립적인 같은 길이 묶음의 눈금 수·수치 각도·길이·원기둥 반지름·높이·뒤쪽 점선 호·사각뿔 밑면 중심·높이선·함수 영역·접선을 고의로 누락하거나 잘못 붙인 경우를 거부하는 회귀 검사를 추가했다.
- 이어서 원·부채꼴/호 원샷 6개를 추가해 앱 원샷 합계 17개를 확인했다. 반지름·중심각·동일 길이 표식·부채꼴 음영·호·점 이름을 버린 모델 응답은 적용 전에 거부한다. 작은 원은 확대하고 큰 원은 축소하되, 빈 기본 화면의 첫 생성에만 적용한다. 전체 테스트는 450건 통과했고 복합 45종·기존 100종은 그대로 오류 0건이다. 이 결과는 확인한 문장 형식에 한정된다.
- 수평선 `y=c`와 함수 사이의 색칠을 추가하면서 앱 원샷 합계는 20개가 됐다. 함수 8개·평면도형 2개·원 6개·입체 4개다. 전체 테스트 453건, 복합 45종·기존 100종은 모두 오류 0건이다. 이 세 함수 사례의 저장 가능한 프로젝트도 남겼다.
- 2026-09-24에는 수평선 `c`를 십진 수치로만 해석했다. 이 제한은 2026-09-25 후속 검증에서 유한한 상수식과 명시적인 구간별 함수로 확대했다. 위 후속 검증의 지원 범위와 남은 제한을 따른다.
- `functionRegion`은 화면용 경계 샘플링을 사용한다. 극점 감지는 보수적인 휴리스틱이며 임의의 불연속 함수를 수학적으로 완전 판정하지는 못한다. 표본 45종 밖의 새 구도는 계속 확인해야 한다.
- HWPX 시험지의 13pt·11pt 수식, 68.2mm 인쇄 폭과 실제 PDF 배치는 이번 캔버스 검수에 포함하지 않았다. 한글 출력에는 `pbj-exam-hwpx`의 실측·인쇄 검사를 적용해야 한다.
- 스킬의 보조 `quick_validate.py`는 현재 번들 Python에 PyYAML이 없어 실행되지 않았다. 스킬의 JSON 파일은 파싱했고 frontmatter·참조 경로는 직접 확인했다.
