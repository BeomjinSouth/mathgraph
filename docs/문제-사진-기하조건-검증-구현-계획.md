# 문제 사진 기하 조건 검증 구현 계획

## 목표

문제 사진을 장면 데이터로 바꿀 때, 등변 표식과 실제 좌표가 어긋나거나 질문에서 요구한 각의 변이 빠진 그림을 적용하기 전에 찾아낸다.

## 구현 범위

1. 정적인 두 선분에 붙은 등길이 표식은 실제 길이를 계산하여 허용 오차 안에서 같은지 검사한다.
2. `mustDraw`에 적힌 구할 각은 꼭짓점과 양쪽 변이 모두 선분·직선·반직선·다각형 변으로 그려졌는지 검사한다.
3. 검증에 실패하면 기존 문제 사진 복구 흐름으로 한 번 더 장면 생성을 요청하고, 실패 원인을 다음 요청에 전달한다.
4. 원래 문제 사진, API 키, 모델의 비공개 추론 과정은 저장하거나 기록하지 않는다.

## 이번 사례에 적용한 기준

- 원문 조건 `AB=AC`를 `AB=CD`처럼 다른 선분에 표시한 경우에는 실제 길이가 달라서 거절한다.
- 원문 조건 `AD=BC`가 실제 좌표와 맞지 않으면 거절한다.
- `∠DBC`를 구하는 문제에서 `BD`가 없으면 거절한다.
- `AD`가 `AC`를 나누어도, 원문이 `AC`를 명시하면 장면에는 전체 선분 `AC`를 유지하도록 생성 지침을 보강한다.

## 완료 기준과 검증

- 잘못된 사례의 두 등길이 표식이 각각 오류로 검출된다.
- 올바른 이등변삼각형과 `AD=BC` 구성은 통과한다.
- `BD`가 빠진 `∠DBC`는 오류로 검출된다.
- 문제 사진 복구 흐름이 검증 오류를 받아 한 번 재시도하는 기존 통합 검사가 통과한다.
- 전체 테스트와 정적 빌드가 통과한다.

## 범위 밖

- 실제 OpenAI API 호출 및 비용 발생 검증
- 사용자의 원본 사진이나 모델 내부 추론 과정 저장
- 자유롭게 끌어 놓는 도형의 모든 기하 관계를 실시간으로 강제하는 기능
