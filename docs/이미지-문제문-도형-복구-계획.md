# 이미지 문제문 도형 복구 계획

## 목표

수학 문제 본문만 보이는 이미지를 첨부했을 때 빈 `operations`를 성공으로 처리하지 않는다. 인쇄된 도식이 없으면 문제문에 명시된 도형 조건을 읽어 편집 가능한 시험지용 도형을 만들고, 복구가 실패해도 내부 검증 문구를 사용자에게 그대로 노출하지 않는다.

## 관찰한 실패

- 이미지 단독 첨부는 `recreate` 모드로 이미지 분석을 요청한다.
- 첫 응답이 `{\"operations\":[]}`이면 `validateIntent()`가 이를 통과시킨다.
- 기존 1회 복구 경로가 실행되지 않은 채 `processAIJSON()`에서 `operations is empty.` 오류가 발생한다.
- 현재 재현 프롬프트는 이미 보이는 도식을 우선하지만, 도식 없이 문제문만 있는 경우의 처리 순서가 명확하지 않다.

## 범위

1. 이미지 분석의 사전 검증에서 빈 연산을 실패로 판정하여 기존 1회 복구 경로로 보낸다.
2. 재현 우선순위를 `보이는 도식 재현 → 도식이 없으면 명시된 문제 조건으로 구성`으로 분리한다.
3. 빈 연산 복구에만 문제문 기반 구성을 안내하고, 다른 오류의 복구 규칙은 넓히지 않는다.
4. 최종 검증 실패 메시지를 학생·교사가 이해할 수 있는 한국어 안내로 바꾼다.
5. 목표 문제 이미지로 브라우저에서 실제 결과와 기하 관계를 확인한다.

## 범위에서 제외

- 새로운 이미지 분석 모드 또는 새 API를 추가하지 않는다.
- 모델·가격·요청 횟수 정책을 바꾸지 않는다. 기존 1회 복구만 사용한다.
- 참조 ID 검증 순서를 이번 수정에서 바꾸지 않는다.
- 문제의 풀이와 정답은 생성하지 않는다.

## 적용 기준과 Skills

- `mathgraph-drawing`: GraphA 연산과 입체도형 생성 규칙을 따른다.
- `openai-vibecoding-context`, `openai-docs`: Responses API의 `input_image` 및 구조화 출력 계약을 확인한다.
- `pbj-ui-copy`: 내부 오류 대신 다음 행동을 알려 주는 한국어 문구를 사용한다.
- `frontend-testing-debugging`, `playwright-interactive`, `browser:control-in-app-browser`: 단위 테스트 뒤 실제 브라우저 흐름을 확인한다.
- `pbj-advisory-gpt`: 독립 검토에서 빈 연산 수정과 참조 검증 변경을 분리하고, 복구 요청에도 원본 이미지가 포함되는지 테스트하라는 의견을 채택했다.

## 완료 기준

- 첫 응답이 빈 연산이면 성공하지 않고 정확히 한 번 복구를 요청한다.
- 첫 요청과 복구 요청 모두 `input_image`를 포함한다.
- 복구 응답도 비어 있으면 더 재시도하지 않고 이해 가능한 안내를 표시한다.
- 프롬프트에 보이는 도식 우선, 도식 부재 시 문제문 조건 사용, 본문 복사 금지, 풀이·정답 생성 금지가 함께 명시된다.
- 기존 이미지 재현과 선택 객체 패치 테스트가 통과한다.
- 동일 문제 이미지를 업로드했을 때 O-ABCD와 O-EFGH, 공통 꼭짓점 O, E/F/G/H의 대응 모서리 위 관계를 화면에서 확인한다.

### 검증 결과

- 빈 첫 응답은 성공 처리되지 않고 한 번의 복구 요청으로 전환된다.
- 원본 문제 이미지는 첫 요청과 복구 요청에 같은 input_image로 포함된다.
- 독립 자문 과정에서 발견한 화면 픽셀 좌표 문제를 막기 위해 이미지 재현 점 좌표를 기본 화면의 수학 좌표 범위(절댓값 20 이하)로 검증하고, 범위를 벗어나면 관계를 유지한 채 다시 축소하도록 했다.
- 같은 문제 이미지의 모의 브라우저 흐름에서 첫 응답을 빈 연산으로 주었을 때 gpt-5.4-mini → gpt-5.5 복구 후 11개 객체가 생성됐다.
- 최종 화면에서 O-ABCD와 O-EFGH가 꼭짓점 O를 공유하고, E/F/G/H가 각각 OA/OB/OC/OD 위 같은 비율에 놓이며 숨은선이 점선으로 표시되는 것을 확인했다.
- npm.cmd test 335/335, npm.cmd run vercel-build 335/335 및 정적 빌드, git diff --check가 통과했다.
