# 앱에서 그림을 만들고 확인하는 방법

앱의 자연어 입력과 사진 업로드에는 다음 흐름이 자동으로 이어진다.

여기서 원샷은 **사용자가 문장을 한 번 입력하고 생성 버튼을 한 번 누르면 추가 수정 지시나 초안 반영 클릭 없이 검사를 통과한 결과가 나오는 것**이다. API 호출 한 회만으로 끝난다는 뜻은 아니다. 최초 생성의 의미 수정과 이미지 확인·수정은 앱 내부에서 이어지며, 초안 반영을 요구하거나 실패한 결과는 원샷 성공으로 세지 않는다.

1. 필요한 기능 설명과 현재 그림을 참조하여 도형 명령을 만든다.
2. 지원 형식·참조 관계·해석 가능한 길이와 각 등의 조건을 검사하고 표시를 배치한다.
3. 캔버스와 별도의 임시 그림을 실제 앱 렌더러로 그린다.
4. 선택한 AI 제공자에게 원래 요청·현재 객체·도형 명령·실제 그림을 보내 조건과 배치를 다시 확인한다. 사진 요청에는 원본 사진도 함께 보낸다.
5. 수정이 필요하면 전체 후보를 한 번 고치고 다시 그려 확인한다. 최종 통과 결과만 캔버스에 반영한다.

빈 기본 화면의 새 도형은 좌표를 바꾸지 않고 화면의 중심과 배율을 맞춘다. 요청에 좌표평면이 있으면 네이티브 좌표축을 준비한다. 최종 배율에서 점 이름·치수·함수식의 전체 글자 상자를 다시 배치하며, 모델이 제안한 작은 기본 글자도 24px부터 확인한다. 사용자가 지정한 글자 크기와 기존 교사 객체·수동 화면은 유지한다. 밖으로 빼고 항상 지시 화살표를 쓰도록 제안한 각도식은 다시 안으로 집어넣지 않는다.

## 화면에서 확인할 사항

생성 중에는 `그림 생성 중`, 검토 중에는 `그림 확인 중`, 수정 뒤에는 `표시 수정 후 다시 확인 중`이 표시된다. `중단` 버튼으로 멈출 수 있다. 진행 중에는 다른 AI 요청을 중복 실행하지 않는다.

완료 뒤에는 `조건별 확인 결과`를 펼쳐 AI가 확인한 조건과 근거를 볼 수 있다. AI에게는 명시한 조건마다 별도로 확인하고, 각도 숫자와 호의 연결·길이 숫자와 점선 호·점 이름·화살표 교차·잘림도 확인하도록 지시한다.

검토를 끝내지 못했으면 자동 반영을 보류한다. 초안 이미지와 확인하지 못한 내용을 본 뒤 `초안 반영`을 누를 수 있다. 이때 화면은 확인 필요 상태로 남는다. 요청 중 또는 초안 대기 중에 그림·확대율·선택·AI 설정이 바뀌면 오래된 결과는 반영하지 않는다. 다시 요청하면 이전 초안도 무효가 된다.

기존 객체와 교사가 옮긴 라벨을 임시 장면에 그대로 복사한다. 검토 수정은 원래 기존 객체 수정 대상·필드의 범위를 넓힐 수 없다. 잠긴 객체의 변경과 연쇄 삭제도 차단한다. 최종 결과는 한 번의 실행 취소로 되돌릴 수 있고, 곡선 화살표와 치수 위치는 기존 프로젝트 저장 방식으로 보존된다.

## 사용량과 한계

- OpenAI·Gemini의 기존 선택과 인증 방식을 사용한다. 검토에는 추가 호출이 1~2회 발생하며 사용량과 대기 시간이 늘어난다. 검토 한 회의 대기 제한은 OpenAI 240초, Gemini 90초다. 생성 단계의 기존 형식 수정 호출은 별도로 발생할 수 있다. 검토의 새 생성 객체는 필요한 필드만 담는 유형별 구조화 형식을 사용하여, 관계없는 null 필드 때문에 긴 수정 응답이 잘리는 일을 줄인다. 원래 후보의 필드·새 유형·기존 객체 수정은 계속 지원한다.
- API 연결이 없는 로컬 생성은 기존 지원 요청을 그린다. 이 경우 AI 이미지 확인 미실시를 화면에 표시한다.
- AI의 통과 판정은 교사 승인, 인쇄 검수, 모든 수학 조건의 완전한 증명이 아니다. 복잡하거나 모호한 문제의 모델 성공률은 별도 실제 호출 평가가 필요하다.
- 검토 결과는 현재 페이지의 `window.app.lastDrawingReview`와 채팅에 남는다. 사진 진단 기록에는 검토 횟수와 상태만 추가한다. 원본 이미지와 전체 검토 문구를 별도 진단 저장소에 저장하지 않는다.

## 구현 연결과 회귀 검증

앱의 `processAICommand`와 `handleImageUpload`가 `reviewAndApplyGeneratedDrawing`을 호출한다. `DrawingPreview`는 기존 적용·화면 맞춤·렌더 경로를 임시 객체에서 실행한다. `DrawingReview`는 호출 상한·판정·수정 범위를 관리하고 `AIService.reviewRenderedDrawing`은 선택한 제공자로 이미지와 조건을 전달한다. 검토 응답은 대화 기록에 추가하지 않으며, 실제 반영한 도형 명령만 후속 대화의 결과로 남긴다.

직접 GraphA JSON을 붙여 넣는 경로, Codex의 그림 제작 스킬과 기존 제작 스크립트는 기존 흐름을 유지한다. 치수와 곡선 화살표의 사용 시점·필드는 [치수 배치 안내](치수-배치와-곡선-화살표-사용법.md)에 있다.

`node scripts/verify-ai-drawing-review.mjs`는 실제 브라우저와 고정 제공자 응답으로 생성·렌더·수정·재검토·반영·중단·보류·저장·모바일 조작을 확인한다. 결과와 PNG는 `output/ai-drawing-review`에 남는다. 이 검사는 실제 외부 모델의 정확도 평가와 구분한다.
