# 치수 배치와 곡선 화살표

## 다음 그림 작업의 진입 경로

이 프로젝트에서는 문제 조건이나 원본 그림을 받으면 `AGENTS.md → mathgraph-drawing → retrieval-index.json`을 따라 필요한 기능과 이 문서를 읽는다. 앱 안의 AI는 `AnnotationGuide.js`를 프롬프트에 직접 받는다. 사용자가 매번 점선·각도·화살표 규칙을 다시 설명할 필요는 없다.

작업 순서는 **조건 확인 → 지원 객체로 생성 → 실제 렌더의 배치·수학 조건 대조 → 필요한 부분만 수정 → 편집 파일과 그림 저장**이다. JSON 생성이나 단위 테스트 통과만으로 그림을 완성했다고 판단하지 않는다. 기존 그림에서는 교사 좌표·수동 배치를 보존한다.

곡선 화살표를 언제 쓰는지는 아래 기준으로 판단한다. 외부 모델을 사용할 수 없을 때의 로컬 생성은 정해진 문장 패턴에 한정된다. 임의 문항의 무조건적인 원샷 성공이나 다른 프로젝트·운영 사이트의 배포 상태까지 이 지침이 보장하지는 않는다.

## 언제 사용하는가

각도 숫자는 해당 각의 내부 이등분선 쪽, 호에서 글자가 닿지 않을 정도로 띄운 곳이 기본 위치다. 글자 상자 전체가 내각 안에서 읽히면 거리가 조금 멀어져도 화살표를 붙이지 않는다. 좁은 예각·혼잡한 교점·긴 식 때문에 안에 넣을 수 없으면 **삼각형 또는 다각형의 실제 바깥**으로 옮긴다. 이때 **숫자에서 해당 각도 호로 향하는 곡선 지시 화살표**를 사용한다. 화살촉은 호에서 약 7px 떨어뜨리고 선 굵기에 비례해 키운다. 꼭짓점을 가리키지 않는다. 각도 객체에 붙어 있어 숫자·호·꼭짓점이 움직여도 연결을 유지한다.

| 상황 | 설정 |
|---|---|
| 글자 상자 전체가 내각 안에 있고 소속이 명확함 | `leaderMode:"auto"` — 불필요한 화살표를 그리지 않음 |
| 숫자를 밖으로 옮겨 다른 각과 혼동할 수 있음 | `labelOffset`으로 이동하고 `leaderMode:"auto"` |
| 사용자가 곡선 화살표를 명시적으로 요청함 | `leaderMode:"always"` |
| 사용자가 연결 화살표를 없애 달라고 함 | `leaderMode:"none"` |
| 곡선이 다른 글자를 지나감 | `leaderCurvature` 조절 후 실제 렌더 확인 |

자동 모드는 글자 상자와 내각·해당 도형의 경계를 확인한다. 모든 변·글자와의 교차를 자동으로 피하지는 않는다. `annotationArrow` 별칭은 기존 **직선 벡터**이므로 각도 지시선 대신 사용하지 않는다. 독립 장식용 곡선 도구로 설명하지 않는다.

## 화면에서 조절하기

1. 각도 도구로 첫 점 → 꼭짓점 → 끝 점을 선택한다. 길이 도구는 선분을 클릭한다.
2. 각도 숫자를 드래그하면 숫자만 이동한다. 글자 상자가 각이나 도형의 바깥으로 이동하면 화살표가 나타난다.
3. 각도 호를 잡으면 호 크기를 바꿀 수 있다. 직각은 보이는 ㄱ 선을 잡는다. 화살표 곡선이나 선택 시 보이는 둥근 손잡이를 잡으면 휘어짐을 바꾼다.
4. 속성의 `지시 화살표`에서 자동·항상·숨김을 선택한다. `화살표 휘어짐`과 `호 반지름`도 조절할 수 있다.
5. 새 길이 숫자는 `호에 붙임`이 기본이다. 숫자를 이동하면 호도 그 위치를 지나도록 변한다. `자유 이동`은 예전처럼 숫자만 움직인다. `점선 길이`와 `점선 간격`을 따로 조절한다.
6. `도형 표시 정렬`은 보이는 도형의 치수 숫자를 기본 위치로 돌리고 점 이름을 인접한 변의 바깥쪽으로 정리한다. 점 좌표는 바꾸지 않는다. 수동 배치를 다시 정리하고 싶을 때만 누른다. 실행 취소할 수 있다.

새 수동 치수 생성 시 사용자가 옮기지 않은 관련 점 이름만 정리한다. 구형 저장 파일의 각도 숫자 기준점과 자유 길이 숫자 위치는 유지한다. 예전 숫자를 호에 붙이려면 속성에서 바꾸거나 표시 정렬을 실행한다.

## GraphA 필드

새 치수는 24px를 기본으로 하고 그림 크기에 따라 24~30px부터 확인한다. 점 이름도 함께 읽히는 크기인지 본다. 정수 각도·길이는 `40°`·`6cm`처럼 쓴다. 단순 수치의 불필요한 소수 0만 없애고 실제 소수·식·변수는 보존한다. 같은 각이 한 묶음이면 각 호에 한 줄씩 표시하며, 서로 독립인 여러 같음 묶음은 표식 수로 구별한다. 기존 수동 크기와 좌표는 수정 요청 없이 바꾸지 않는다.

| 대상 | 필드 | 의미 |
|---|---|---|
| 각도 | `leaderMode` | `auto`(기본), `always`, `none` |
| 각도 | `leaderCurvature` | 제어점 휘어짐, 화면 px, −300~300, 기본 28 |
| 각도 | `labelPlacement` | 새 도형은 `centered`, 예전 위치 보존은 `legacy` |
| 각도 | `labelOffset` | 숫자 이동량, 수학 좌표 단위 |
| 길이 | `curvature` | 길이 호 휘어짐, 화면 px. 부호로 양쪽을 구분 |
| 길이 | `dashLength`, `dashGap` | 점선 길이와 빈 간격, 각각 1~40px. 새 기본값 7/7 |
| 길이 | `labelOnCurve` | `true`이면 숫자가 호의 틈에 놓임 |
| 길이 | `labelT` | 호 위 숫자 위치, 0.1~0.9. 기본 0.5는 중앙 |
| 공통 | `labelFontSize`, `precision`, `customText` | 글씨 크기, 소수 자리, 사용자 표시 내용 |

새 길이는 `labelOnCurve:true`, `labelT:0.5`를 권장하며 `labelOffset`은 생략한다. 자동 배치는 글자가 호의 틈에 걸치는 범위에서만 작은 광학 보정값을 넣을 수 있다. 붙임 모드에서 직접 드래그하면 그 보정값은 0으로 돌아가고 호가 숫자를 따라간다. 자유 이동 모드와 구형 파일은 기존 위치를 유지한다. 자동 수치는 점을 움직이면 다시 계산하지만 `customText`는 지정한 내용으로 남는다.

## AI 생성·수정 예시

기존 각도 숫자를 옮기고 화살표를 붙이는 예다. `angle_A`는 실제 객체 ID로 대체한다. 점을 새로 만들거나 원래 좌표를 이동하지 않는다.

```json
{"operations":[{"op":"update","id":"angle_A","labelOffset":{"x":-1.2,"y":0.8},"leaderMode":"always","leaderCurvature":28}]}
```

기존 선분 `AB` 바깥에 길이 호를 만들고 숫자를 그 틈에 놓는 예다. 도형 방향에 맞춰 곡률 부호를 고른다.

```json
{"operations":[{"op":"create","id":"length_AB","type":"lengthDimension","segmentId":"AB","curvature":-60,"labelOnCurve":true,"labelT":0.5,"dashLength":7,"dashGap":8,"labelFontSize":20,"customText":"6 cm"}]}
```

AI는 내부 배치를 먼저 시도하고, 겹침이 남으면 가까운 바깥 빈 공간과 곡선 화살표를 사용한다. 긴 수식을 이유로 호를 과도하게 키우거나 다른 꼭짓점의 각으로 바꾸지 않는다. 각도 숫자의 소속, 길이 호의 틈, 점 이름을 함께 검사한다. 기존 그림 수정에서는 요청한 객체와 교사 위치를 보존한다.

## AI 연결과 검증

- 명시한 길이·각의 숫자는 글자 전체의 값과 단위를 확인한다. `40+10°`를 40°로, `6/2 cm`를 6cm로 읽지 않는다. 같은 값을 나타내는 유한 상수식과 단위 환산은 허용한다. 자동 표시의 소수 자릿수가 부족해 요청값이 달라지면 통과시키지 않는다. `A각 20°`, `각 BAC는 20도`처럼 이름과 숫자가 명시된 한글 각 표기도 확인한다. 이는 임의 자연어·변수식의 완전한 해석은 아니다.
- 수치 각과 함께 `A의 각도 호에 (2x+15)°를 적어줘`처럼 그 각의 표시 식을 명시하면 해당 식은 그대로 표시하고 실제 각의 수치는 따로 검사한다. 요청하지 않은 변수식, 다른 각의 식, 잘못된 반직선이나 수치로 바꾸는 경우는 통과시키지 않는다. 현재 이 예외는 괄호 안의 x·y·z 식과 명시적인 표시 요청에 한정한다.
- `AB=CD=5cm`처럼 같은 길이를 명시한 묶음에는 실제 길이와 같은 길이 표식을 확인한 뒤 대표 변의 치수 호를 사용할 수 있다. 모든 맞은변에 중복 숫자를 요구하지 않는다. 단순히 두 변의 수치가 같다는 이유로 다른 변의 치수선을 대신 인정하지 않는다.
- 구간별 함수에서 `1<=x<=2의 빈 구간`처럼 제외 구간을 덧붙일 수 있다. 이 조건이 실제 조각의 정의역이나 포함된 끝점과 겹치면 거부한다. `각 조각`, `각 식`은 각도 작도를 뜻하지 않는다.
- 실제 그림 검토는 OpenAI 호출당 최대 240초, Gemini는 기존 90초를 사용한다. 수정은 최대 한 번이며 수정 후 다시 검사한다. 시간 초과·불확실한 판정은 성공이 아니고 사용자의 중단 요청은 계속 우선한다.
- `js/ai/AnnotationGuide.js`가 모든 제공자의 시스템 프롬프트와 기능 검색 문맥에 포함된다. 신규 치수 필드는 구조화 출력·검사·패치·장면 변환으로 전달한다.
- 새 도형은 `DiagramQualityEnhancer`와 실제 글꼴을 쓰는 `RenderedLabelLayout`에서 배치를 정리한다. 저장된 교사 그림을 자동 재배치하지 않는다.
- `tests/annotation-leader.test.js`에서 연결점·직각·클릭·저장·undo/redo·AI 전달을 검사한다. 실제 화면의 생성·드래그·내보내기는 추가로 검수한다.
- 외부 모델의 임의 문항 전체 성공률이나 HWP 인쇄를 보장하지 않는다. 이번 작업의 실행 결과와 제한은 `docs/progress-log.md`에서 확인한다.
