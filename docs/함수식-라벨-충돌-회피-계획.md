# 함수식 라벨 충돌 회피 계획

## 문제

문제 사진으로 만든 함수 그래프에서 함수식 라벨이 화면 중앙의 곡선 위에 자동 배치된다. 화면 중앙이 교점이나 다른 직선과 겹치면 `P` 같은 점 이름, 점 표식, 그래프, 함수식이 한곳에 포개진다. 현재 함수 객체는 자동으로 계산한 위치를 수동 고정 위치와 같은 필드에 저장하므로, 함수에 지정된 `labelOffset`도 첫 렌더링 뒤에는 적용되지 않는다.

## 목표

- 함수식 라벨이 이름이 있는 점, 교점, 직선, 다른 함수식과 겹치지 않도록 앱이 결정적으로 위치를 고른다.
- 계산용 `sqrt(...)`는 화면에서 근호가 있는 수식으로 표시한다.
- `sqrt(x-2)`나 점 `P`에만 맞춘 예외 처리를 두지 않는다.
- 사용자가 직접 옮긴 함수식 위치는 그대로 보존한다.
- 사진 분석 모델의 추가 호출 없이 로컬 후처리만 사용한다.

## 구현 범위

1. 함수 객체가 자동 위치와 사용자가 고정한 위치를 구분하도록 고친다.
2. `DiagramQualityEnhancer`가 함수의 보이는 구간을 표본화하고, 점·교점·선·다른 함수 라벨과의 충돌이 가장 적은 후보를 선택한다.
3. 함수-직선과 함수-함수 교점을 계산하여 모델이 교점을 좌표로 직접 적지 않아도 장애물로 인식한다.
4. 함수식의 예상 폭과 높이를 포함한 사각형으로 충돌을 검사한다.
5. 수식 파서가 `sqrt(...)`와 `\\sqrt{...}`를 근호 구조로 변환하여 그린다.

## 완료 기준

- 제보된 역함수 문제에서 `P`와 `f(x)=sqrt(x-2)`가 분리된다.
- 같은 라벨이 `sqrt`라는 글자 대신 `√(x−2)` 형태로 보인다.
- 두 함수와 한 직선이 있는 일반 회귀 사례에서도 라벨끼리 겹치지 않는다.
- 기존 수동 라벨 드래그·저장·불러오기 동작이 유지된다.
- 집중 테스트, 전체 테스트, 정적 빌드, 실제 브라우저 확인을 통과한다.
