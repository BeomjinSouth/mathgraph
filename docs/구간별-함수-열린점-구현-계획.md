# 구간별 함수 열린 점 구현 계획

## 목표

좌표평면의 구간별 함수에서 열린 점과 닫힌 점을 정확히 구분하고, 함수 구간·점선 보조선·점의 포함 여부를 시험지 그림으로 재현한다. 특정 그림의 좌표를 하드코딩하지 않고 모든 점 객체에 재사용할 수 있는 스타일로 구현한다.

## 사용자 장면

- 왼쪽 직선은 `y=-x-2`이고 `x=-1`에서 열린 점 `(-1,-1)`을 갖는다.
- 가운데 곡선은 `y=1-x^3`이고 `-1<x<=1`에서 열린 점 `(-1,2)`, 닫힌 점 `(1,0)`을 갖는다.
- 함수값 `f(-1)=1`은 닫힌 점 `(-1,1)`로 표시한다.
- 오른쪽 직선은 `y=-x+2`이고 `x=1`에서 열린 점 `(1,1)`을 갖는다.
- `x=-1`, `x=1`, `y=-1`, `y=1`, `y=2`의 점선 보조선을 보존한다.

## 일반 기능

- 점 계열 객체에 `pointStyle: "closed" | "open"`을 추가한다.
- 기본값은 기존과 같은 `closed`로 두어 기존 프로젝트와 그림을 바꾸지 않는다.
- `open`은 검은 테두리와 캔버스 배경색 내부를 가진 빈 원으로 렌더링한다.
- 자유점뿐 아니라 선 위의 점, 원 위의 점, 교점, 중점, 원의 중심점에도 같은 표현을 적용한다.
- 저장·불러오기, AI 구조화 출력, 장면 그래프 컴파일, 생성·수정 패치에서 값을 유지한다.
- 허용하지 않는 값은 스키마 검증에서 거부한다.

## 영향 파일

- `js/objects/GeoObject.js`, `js/objects/Point.js`, `js/core/Canvas.js`
- `js/ai/AIService.js`, `js/ai/SchemaValidator.js`, `js/ai/PatchApplier.js`, `js/ai/SceneGraphCompiler.js`
- AI 참고 문서와 `mathgraph-drawing` 참고 자료
- 열린·닫힌 점 렌더링과 AI 계약을 확인하는 테스트

## 완료 기준

- 기존 점은 닫힌 점으로 그대로 렌더링된다.
- 열린 점은 내부가 비고 테두리가 보인다.
- `pointStyle`이 저장·복원되고 생성·수정 패치에 반영된다.
- `pointStyle="half-open"` 같은 값은 거부된다.
- 제시된 구간별 함수 그림을 정확한 세 함수 구간, 열린 점 3개, 닫힌 점 2개, 점선 5개로 브라우저에서 재현한다.
- 브라우저에서 준비 완료 상태와 생성 개수를 확인하고 경고·오류 로그가 0건이어야 한다.
- 관련 테스트, 전체 테스트, 정적 빌드, `git diff --check`가 통과해야 한다.

## 검증 경계

- 실제 OpenAI 이미지 업로드는 API 키가 있는 환경에서만 확인할 수 있다. 로컬 게스트 검증은 정확한 GraphA JSON을 직접 입력하여 렌더링·계약·브라우저 동작을 확인한다.
- 이번 작업에서는 운영 배포를 실행하지 않는다.

## 완료 결과

- 점 계열 객체의 공통 속성으로 `pointStyle`을 구현하고 기본값을 `closed`로 유지했다.
- 캔버스와 SVG 내보내기에서 `open`은 검은 테두리와 배경색 내부를 가진 빈 원으로 표시된다.
- AI 구조화 출력, 스키마 검증, 생성·수정 패치, 장면 그래프 컴파일, 저장·복원을 같은 계약으로 연결했다.
- 구현 전 집중 테스트 3건이 실패하는 것을 확인했고, 구현 후 3/3이 통과했다.
- `npm.cmd run vercel-build`에서 전체 348/348 테스트와 정적 빌드가 통과했다.
- 최신 로컬 빌드를 브라우저에서 렌더링하여 `16 created`, 열린점 3개, 닫힌점 2개, 점선 5개를 확인했다. 마지막 새로고침 뒤에는 새 경고·오류가 없었다.
- 검증 화면은 `mathgraph-piecewise-open-closed-points.png`로 보관했다.
- 게스트 환경에 API 키가 없어 실제 OpenAI 이미지 업로드 호출과 운영 배포는 실행하지 않았다.
