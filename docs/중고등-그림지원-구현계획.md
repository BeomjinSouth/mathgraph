# 중·고등 수학 그림 구현 계획

## 구현 순서

1. 기존 HEAD에서 격리된 `feat/중고등-수학그림-확장` 브랜치를 사용한다. 원래 폴더의 HWPX와 미추적 산출물은 보존한다.
2. 데이터 기반 통계 객체, 고리 부채꼴, 전개도를 구현한다. 공통 그리기 명령을 Canvas와 SVG에 재사용하여 내보내기 누락을 방지한다.
3. ObjectManager, PatchApplier, SchemaValidator, AI strict schema, SceneGraphCompiler와 속성 편집을 연결한다.
4. 수치가 명확한 한국어 요청에는 로컬 생성기를 제공한다. 자료 없는 요청은 오류를 표시하고 값을 만들어내지 않는다. 기존 객체 수정 요청을 새 생성으로 바꾸지 않는다.
5. 새 요청군과 기존 기하·함수 요청을 자동 검사하고 실제 앱에서 저장/실행 취소/내보내기/화면 맞춤을 검증한다.
6. 매뉴얼·스킬·지원 범위표·진행 기록을 결과에 맞춰 갱신하고 작업 브랜치를 푸시한다.

## 검증과 복구

최소 회귀 검사를 먼저 실행하고 최종 `npm run vercel-build`로 전체 테스트와 빌드를 실행한다. 잘못된 입력은 기존 캔버스를 보존해야 한다. 새 그림이 화면에서 잘리지 않고 SVG에 빠짐없이 포함되는지 확인한다. 새 기능 파일과 연결부만 변경하며, 문제가 있으면 이번 커밋 단위로 되돌릴 수 있게 한다.

## 적용 자료와 운영 상태

- `mathgraph-drawing`: 객체 계약, 교사 라벨 보정, 실제 렌더 검수.
- `pbj-ui-copy`: 기존 속성 패널의 필요한 입력 라벨과 구체적 오류 문구.
- `routing-personal-playbooks`: 상태 검사 및 읽기 전용 라우팅을 실행했으나 unavailable. 일반/프로젝트 기준으로 진행하며 기억을 추측하지 않음.
- `solo-ai-workbench`: 두 설치 경로와 skills 목록에서 파일을 찾지 못함. AGENTS의 격리·단일 작성자·증거 보존 원칙은 준수.
- 로컬/원격 main은 `eb45837`. Vercel CLI 조회에서 Production Branch=main, 운영 배포 READY, 소스 main/eb4583704a374c7d5db2ae4bd7d02380374a1a71, 운영 별칭 mathgraph-five.vercel.app을 확인했다. 운영에만 있는 변경은 발견하지 않았다. Vercel connector의 get_project는 도구 입력 계약 오류를 반환하여 CLI 조회로 전환했다.
- 기존 Design.md/Soul.md는 루트에 없음. 기존 교사 도구 UI와 요구사항을 기준으로 좁은 속성 편집만 추가하므로 화면 재설계나 이미지 시안은 필요 없음.
