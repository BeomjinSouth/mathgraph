## 공통 원인과 수정

1. GraphA 생성에서 길이 호의 `curvature`와 정밀도가 실제 객체에 전달되지 않았다. 음수·0·큰 곡률을 생성·저장·복원까지 보존한다.
2. +180°/-180° 경계에서 방향각의 평균이 반대편을 가리켰다. 같은 회전 구간으로 정규화해 각도식과 동일각 표식을 그린다.
3. 기존 후처리는 점 이름의 대략적인 방향만 정했다. 새 생성에서는 실제 글자 치수와 선의 픽셀, 다른 라벨을 비교한다. 각도식은 내부 이등분선, 길이식은 자기 호의 틈과 연결된 범위로 제한한다.
4. 길이식 뒤의 흰 상자가 다른 선까지 지웠다. 해당 곡선만 실제로 끊고 근호의 실측 높이도 반영한다.
5. 웹 글꼴이 늦게 로드되면 같은 파일을 다시 열었을 때 치수 글자의 폭이 달라졌다. 점 이름과 같은 수학용 로컬 글꼴 계열을 사용하며, 실제 앱에서 왕복 출력의 픽셀 동일성을 확인했다.
6. 각뿔이 꼭짓점 객체와 별도로 검은 원을 그렸다. 표식은 원래 점 객체가 담당하게 하고 실제 그리기 호출 검사와 회귀 검사를 추가했다.
7. 명시적 (0,0)이나 작은 오프셋을 자동 위치로 오인했다. 이제 명시값은 그대로 보존한다.
8. AI가 제안한 위치까지 교사 수동 위치처럼 고정하면 잘못된 제안을 고칠 수 없다. 새 AI 생성에서는 제안 위치를 보정하고, 기존 교사 객체·patch 모드와 기본 CLI 입력은 보존하도록 구분했다. 24개 사례에 일부러 잘못된 AI 제안 오프셋을 넣어 검사했고 같은 앱 검사에서 기존 객체와 수동값 보존도 확인했다.

## 반복 개선과 자료 구분

- 초기 75종 중 64종이 걸렸다. 선분 밖 교점을 선분끼리로 지정한 사례는 숨긴 지지 직선을 사용하도록 고쳤다. 앱의 교점 범위 규칙을 바꾸지는 않았다.
- 첫 수정 후 5종, 다음 수정 후 2종, 길이식의 연결성을 강화한 단계에서 1종이 남았다. 부분 길이와 전체 길이 호가 한쪽에 몰린 구도를 조정하고 재검사했다.
- 자동 통과 후 전체 그림을 보며 각뿔의 중복 표식, 근호 표시와 수직선 위치의 불일치, 각기둥 모서리와 길이 호의 겹침을 발견해 고쳤다. 길이 호의 쪽은 뒤쪽 면의 투영 방향을 고려했다.
- 실제 앱 검사의 첫 실패는 새로 만든 객체의 `createdAt` 차이였다. 배치와 무관한 이 항목만 비교에서 제외했다. 그 뒤 발견된 PNG 차이는 웹 글꼴 로딩 문제였으며 렌더러를 수정한 후 통과했다.
- 중간 실패는 `baseline`, `round1`~`round4`, `final-reviewed` 등에 보존했다. 현재 전달 기준은 **verified-v2**다. 초기 일부 시행은 사례 구성도 달랐으므로 직접 수치 비교에는 `baseline-v2`와 최종 동일 입력만 사용한다. v2에서 실제 PNG가 바뀐 것은 E095·E099 두 장이며 다시 시각 확인했다. 나머지 98장은 앞서 확인한 PNG와 바이트가 동일하다.
- 정적 검사 경고는 E017·E021·E025·E026·E030·E031·E034의 위쪽 기준선 7건과 E085의 가까운 두 끝점 1건이다. 전자는 교차 선을 피한 실제 라벨 위치이며 후자는 서로 다른 함수 구간의 끝점이다. 해당 그림에서 연결성과 여백을 확인했다. 수학적 점이나 경고 기준을 바꿔 숨기지 않았다.

## 검증 범위와 한계

- Chrome의 실제 렌더와 700×600 사례 100종을 검사했다. 실제 앱의 왕복 검사는 1440×1000에서 수행했다. 390×844에서도 페이지는 열리지만 기존 측면 패널이 캔버스를 가리는 화면 문제가 남아 있다. 모바일 UI 수정은 이번 도형 생성 작업에 포함하지 않았으며 모바일 통과라고 표현하지 않는다. Browser 스킬이 없어 기존 Playwright를 사용했고 외부 AI API를 호출하지 않았다.
- 조건·유효성·점 위치 보존, 명시한 중점·교점·수선·내분, 라벨 누락·겹침·잘림·표식, 저장 전후 픽셀을 검사한다. 모든 수학 문제의 정답을 검증하는 도구는 아니다.
- 새 도형과 모든 글꼴 환경에 대해 완벽함을 보장하지 않는다. 사용자 위치는 고정하며, 공간이 없으면 입력 구도와 여백을 검토한다.
- HWPX 시험지 100개를 작성한 작업은 아니다. 현재 체크아웃에는 `js/utils/HwpDiagram.js`가 없고 한글 입력 기능은 기존 별도 작업 공간에 있다. 실제 한글 13pt/11pt 수식 배치와 PDF 검수는 `pbj-exam-hwpx` 절차로 별도 수행해야 한다.
- 스킬 기본 검증기는 번들 Python의 `yaml` 모듈 부재로 실행하지 못했다. frontmatter는 변경하지 않았으며 새 참조와 실행 경로를 직접 확인했다. 연결한 실행 도구는 실제로 검증했다.

## 저장소·배포

사용자 HWPX와 24종 원본·수정본은 보존했다. 확인한 원격 main은 `f87468d`, 로컬 main은 `275d9ec`으로 다르며 운영 반영을 진행하지 않았다. 로컬 최종 구현은 `5f358dc`다. 원래 브랜치 푸시는 선행 시험지 산출물 이력까지 전송한다는 이유로 자동 승인 검토가 거절했고 재시도하지 않았다.

이미 원격에 있는 `3353099`에서 출발한 [코드 전용 브랜치](https://github.com/BeomjinSouth/mathgraph/tree/codex/exam-diagrams-100-source-20260922)를 만들고 `b322db5`를 푸시했다. 앱 소스, 검사기, 그림 제작 참조, 이번 검수 문서와 필요한 라벨 편집/프로젝트 저장 수정만 담았다. 시험지 산출물과 선행 시험지 커밋, 생성 이미지/프로젝트는 전송하지 않았다. 새 전송 범위는 자동 승인 검토를 통과했다.

Vercel 프로젝트의 Git 연결이 null이라 새 Preview는 생성되지 않았다. 운영 별칭은 기존 `codex/ai-fallback-recovery`의 `383462a1` 배포를 가리켰으며, main 및 운영 설정을 변경하지 않았다. 자동 연결과 main 정합화는 별도 확인이 필요하다.
