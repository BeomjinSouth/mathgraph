# 이미지 재현 진단 로그 구현 계획

## 영향 범위

- `js/ai/ImageAnalysisTrace.js`: 진단 보고서 생성, 정제, 단계 기록, 작업 차이 계산, 로컬 보존
- `js/ai/AIService.js`: 모델 장면 해석부터 의미 검증까지 단계 기록
- `js/main.js`: 이미지 준비와 캔버스 적용 결과 기록, 조회·내보내기 API 제공
- `tests/image-analysis-trace.test.js`: 기록 계약과 민감정보 차단 검증
- 기존 이미지 분석·장면 파이프라인 테스트: 회귀 검증

## 구현 순서

1. 순수 자바스크립트 진단 모듈을 추가한다.
2. `AIService`의 문제 사진 장면 경로에 시도별 기록을 연결한다.
3. 일반 이미지 경로에도 최소 모델·보정·의미 검사 기록을 연결한다.
4. `GraphAApp.handleImageUpload()`에서 입력 준비 단계를 시작하고, `processAIJSON()`에서 캔버스 적용 단계를 종료한다.
5. 로컬 저장 및 `window.app` 조회·내보내기 메서드를 연결한다.
6. 단위 테스트, 관련 회귀 테스트, 전체 테스트, 빌드를 차례로 실행한다.

## 진단 판정 규칙

- `error`: 가장 먼저 실패한 단계가 `suspectedStage`가 된다.
- `warning`: 단계는 진행됐지만 경고가 있는 상태다.
- `ok`: 해당 단계의 로컬 검사가 통과했다.
- `not_run`: 앞 단계 실패 등으로 실행하지 못했다.
- 로컬 단계가 모두 성공해도 자동 원본 대조가 없으면 전체 판정은 `source_fidelity_unverified`로 끝난다.

## 작업 차이 규칙

- 작업의 `id`가 있으면 `id`를 기준으로 비교한다.
- `id`가 없으면 배열 위치와 `type`을 조합한 임시 키를 쓴다.
- 추가·삭제·변경된 작업을 나누고, 변경된 필드 이름을 기록한다.
- 전체 스냅샷은 크기 제한 정제기를 통과한 값만 보존한다.

## 검증 계획

- 장면에 잘못된 선이 모델 단계부터 있으면 이후 단계에도 같은 ID가 이어지는지 확인한다.
- 보정기가 선을 추가·삭제·변경하면 `changes`가 정확히 기록되는지 확인한다.
- API 키, 토큰, 이미지 데이터 URL, 원문 지시문이 직렬화 결과에 없는지 확인한다.
- 로컬 저장소가 손상되거나 용량 오류를 내도 요청 처리가 실패하지 않는지 확인한다.
- 5건 초과 시 오래된 보고서가 제거되는지 확인한다.
- 캔버스 적용 실패 시 스키마·참조·의미·패치 중 최초 실패 단계가 기록되는지 확인한다.

## 현재 제약

- 자동 시각 비교는 이번 범위에 포함하지 않는다. 따라서 보고서는 “어느 내부 단계에서 무엇이 바뀌었는지”는 보여 주지만, 원본과의 최종 일치 여부를 자동으로 확정하지 않는다.
- `ai-work start`는 `main` 체크아웃에서 기존 미추적 `tmp/`, `output/`, PDF 파일을 감지하여 중단됐다. 사용자 파일을 삭제·이동·숨김 처리하지 않고, 깨끗한 기존 작업 브랜치에서 관련 파일만 수정·커밋한다.
