# 시험 도형 100종 반복 개선

## 요구사항과 완료 기준

사용자가 직접 검수한 24종의 기준을 지키면서 다양한 시험 도형 약 100개를 생성·렌더·수정하고, 반복 결함을 공통 생성/출력 코드에서 예방한다. 개별 시안의 좌표만 손보거나 검사 기준을 낮춰 성공으로 만들지 않는다.

- 평면도형, 교점과 중점, 각도와 길이, 원, 함수와 수직선, 입체도형을 포함한 100개의 재현 가능한 사례를 만든다. 같은 그림의 숫자만 바꾼 사례로 다양성을 대신하지 않는다.
- 각 사례에 수학적 조건, 검사 대상, GraphA 원본, 수정된 프로젝트, 실제 렌더와 결과를 연결한다.
- 첫 실행의 실패를 보존하고 공통 원인을 고친 뒤 같은 입력으로 재검사한다. 최소 2회의 생성→검사→원인 수정 과정을 기록한다. 일부 변형은 마지막 검증용으로 따로 사용한다.
- 점 이름/조건의 겹침과 잘림, 각도식의 소속, 길이 호, 점 표식 예외, 계산용 객체 노출, 저장/불러오기 보존을 확인한다. 화면을 실제로 본 범위와 자동 검사 범위를 구분한다.
- 사용자 수정 좌표·오프셋과 지정된 기하 조건을 보존한다. 검사기가 발견하지 못한 문제는 통과라고 표현하지 않는다.
- 기존 관련 검사와 전체 빌드가 통과하고, 다음 제작에 같은 개선이 적용되는 호출 경로를 확인한다.

## 구현 순서

1. 현재 a370cb0 기준으로 격리한 `codex/exam-diagrams-100-20260922`에서 자료/실행 경로를 조사한다.
2. 다양한 사례 생성기와 실제 MathGraph 객체/캔버스를 쓰는 배치 평가기를 추가한다. API 호출 비용 없이 로컬 생성·검사를 수행한다.
3. 원래 코드의 렌더/저장 실패를 기록하고 영향을 받는 공통 코드를 수정한다.
4. 재생성·실제 그림 검토·회귀 검사를 반복하고 최종 100종의 산출물과 한계를 기록한다.
5. 스킬 참조와 진행 기록을 갱신하고 변경분을 커밋한다. 원격 전송은 기존 차단 이력과 시험지 자료 노출 범위를 먼저 확인한다. 운영 배포는 main 반영 권한 없이 실행하지 않는다.

## 사용 기준과 검증 환경

- `mathgraph-drawing`, 시험 도형 라벨·간격 보정 기준, 보존된 교사 수정 분석을 사용한다.
- `pbj-exam-hwpx`의 점 이름 13pt·조건 11pt·폭 68.2mm는 HWP 내보내기 기준이다. 화면 px 값을 인쇄 수치로 오인하지 않는다.
- 프런트엔드 검증은 로컬 MathGraph 입력→실제 객체 생성→렌더→프로젝트 저장·재로드→내보내기를 확인한다. Browser 스킬이 없어 기존 Playwright를 사용한다.
- 전역 취향 라우터는 현재 `unavailable`을 반환했다. 새로운 기억을 쓰지 않고 프로젝트/현재 요청을 따른다. `solo-ai-workbench`는 설치 목록과 로컬 검색에서 찾지 못하여 격리·증거·복구 원칙을 직접 적용한다.

## 진행

- 25개 구조 × 4개 변형의 100종을 만들고 75종 개발 검사, 25종 분리 검사, 전체 시각 검토를 반복했다.
- 공통 생성/렌더 오류와 사례 구성 오류를 구분해 수정했다. 최종 자동 검사는 100/100 통과했으며 모아보기 9장을 통해 E001~E100 전부를 확인했다.
- 실제 앱의 대표 6종 생성→실행 취소/다시 실행→파일 저장/불러오기→PNG 출력이 통과했다. 명시한 수동 위치와 patch 모드 보존도 확인했다.
- 결과와 한계는 `시험-도형-100종-검수결과.md`에 기록했다. 초기 사용자 HWPX 변경과 24종 교사 수정본은 변경하지 않았다.
