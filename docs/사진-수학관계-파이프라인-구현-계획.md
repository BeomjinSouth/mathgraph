# 사진 수학 관계 파이프라인 구현 계획

## 목표

사용자가 문제 사진만 첨부해도 MathGraph가 문제를 읽고, 수학적 관계와 좌표 배치를 먼저 정리한 뒤 편집 가능한 도형을 만든다. 모델이 사진에서 곧바로 저수준 `operations[]`를 작성하게 두지 않는다.

## 확인된 원인

1. 기존 첫 요청은 `gpt-5.4-mini`가 사진을 읽는 일과 수십 개의 GraphA 필드를 채우는 일을 한 번에 수행했다.
2. 구조화 출력 스키마가 각 객체의 사용하지 않는 필드까지 모두 요구하여 출력이 길어지고 시간 초과 가능성이 커졌다.
3. JSON 문법과 일부 도형 유형은 검증했지만, 원문에서 읽은 필수 요소가 최종 그림에 모두 들어갔는지는 일반적으로 확인하지 못했다.
4. 실패하면 더 비싼 모델에 사진을 다시 보내는 방식이어서 비용과 시간이 모두 불안정했다.
5. 이미 준비되어 있던 `SceneGraphCompiler`가 실제 사진 업로드 경로에는 연결되지 않았다.

## 구현 구조

1. **문제 읽기**: `gpt-5.6-luna`가 원문 사진을 한 번 읽고 간결한 장면 명세를 만든다.
2. **관계와 좌표 계획**: 장면 명세에는 필수 점·선·곡선·영역, 관계, 대표 좌표, 원문 근거, 반드시 그릴 항목을 기록한다.
3. **앱 소유 컴파일**: `SceneGraphCompiler`가 장면 명세를 GraphA `operations[]`로 결정적으로 변환한다.
4. **대조 검증**: 필수 항목이 실제 연산 ID에 연결되었는지, 참조와 좌표가 유효한지 검사한다.
5. **선택적 복구**: 검증이 실패한 경우에만 Luna가 장면 명세를 다시 읽거나 보정한다. 정상 입력에는 추가 이미지 호출을 하지 않는다.

## 모델·비용·시간 결정

- 기본 OpenAI 모델과 문제 사진 분석 모델을 `gpt-5.6-luna`로 바꾼다.
- 문제 사진 분석은 `reasoning.effort: medium`, 단순 변환과 일반 명령은 기존 수준을 유지한다.
- GPT-5.6에서는 글자가 많은 문제 사진의 공간 정보를 보존하도록 `detail: original`을 사용한다.
- 첫 성공 시에는 이미지 API 호출을 한 번만 사용하고 로컬 컴파일로 끝낸다.
- OpenAI 프록시 시간 제한은 240초, 브라우저 제한은 그보다 조금 길게 둔다.
- Vercel 함수의 `maxDuration`은 300초로 명시한다.

## 완료 기준

- 사진 전용 요청이 장면 명세 경로를 사용한다.
- 빈 연산, 누락된 필수 항목, 끊어진 참조, 화면 밖 좌표를 성공으로 처리하지 않는다.
- 역함수와 직선, 반원 위의 점과 내부 도형, 입체도형의 내부 음영 면처럼 서로 다른 문제군을 같은 장면 명세로 표현한다.
- 기존 텍스트 명령과 사진 부분 수정 경로는 깨지지 않는다.
- 집중 테스트, 전체 테스트, 정적 빌드, 실제 배포 확인을 통과한다.
