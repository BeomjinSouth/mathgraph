# 시험 도형 라벨·간격 보정 기준

교사가 직접 고친 MathGraph 프로젝트를 다음 시험 도형 생성에 반영할 때 사용한다. 저장 시각·생성 시각·화면 이동값은 배치 취향으로 단정하지 말고, 점 좌표·라벨 오프셋·가시성·곡률처럼 그림 자체를 바꾼 값만 비교한다.

## 먼저 구분할 것

- 라벨만 어색하면 `labelOffset`을 조정한다.
- 라벨을 2~3글자 높이 이상 멀리 보내야 한다면 점 좌표나 도형 구성을 먼저 고친다.
- 수학적 관계를 나타내기 위한 보조 선분은 계산에 필요해도 화면에서는 `visible:false`로 숨긴다. 같은 위치의 주 도형 선과 보조 선을 겹쳐 그리지 않는다.
- 사용자가 직접 저장한 `labelOffset`과 좌표는 새 자동 배치가 덮어쓰지 않는다.

## point label의 기준선

MathGraph의 점 이름은 `textBaseline='bottom'`으로 그린다. `labelOffset.y`는 글자 중심이 아니라 글자 아래쪽 기준선의 위치다. 따라서 위쪽 이름을 크게 음수로 보내면 글자 높이까지 더해져 꼭짓점에서 과도하게 멀어진다.

글자 크기 27px 안팎에서는 다음 범위부터 검토한다.

| 의도 | 권장 `x` | 권장 `y` | 설명 |
|---|---:|---:|---|
| 점의 위쪽 중앙 | `-10~-5` | `-4~7` | 기준선을 점 가까이에 두면 글자 상자는 위로 올라간다. |
| 점의 아래쪽 중앙 | `-10~-5` | `30~38` | 글자 높이만큼 기준선을 아래로 내린다. |
| 점의 왼쪽 | `-32~-24` | `2~28` | 한 글자 폭과 6~10px 간격을 확보한다. |
| 점의 오른쪽 | `8~16` | `2~28` | 점에서 8px 이상 띄운다. |

도형의 기울기와 주변 선에 따라 범위 안에서 조정하되, 방향 이름만 보고 `y=-20~-30`을 기계적으로 쓰지 않는다.

## 점 간격을 먼저 확보할 것

- 서로 다른 이름이 붙는 점은 기본 배율에서 화면 간격 48px 이상을 확보한다.
- 같은 직선 위에서 연속으로 읽어야 하는 `A-B-P`, `C-D-P` 같은 점은 60~80px 이상을 우선한다.
- 두 점이 너무 가까우면 라벨을 멀리 피하는 대신, 자유롭게 정할 수 있는 정의점의 좌표를 옮긴다.
- 문제에서 좌표나 길이를 정확히 지정했다면 기하 조건을 바꾸지 않는다. 이 경우 확대율·글자 크기·별도 지시선 같은 다른 해결책을 검토한다.

P21에서는 D와 P가 약 10px밖에 떨어지지 않아 D 라벨을 100px가량 옮겨야 했다. D를 같은 직선 위의 `(0,1)`로 옮기면 DP가 약 100px로 벌어지고 작은 오프셋만으로 역할이 분명해진다. 이 사례처럼 큰 라벨 이동은 점 간격 오류의 신호로 본다.

## 길이 호

- 길이 치수의 `curvature`는 양수와 음수 모두 의미가 있으므로 부호를 보존한다.
- 같은 선분의 위·아래 또는 좌·우에 호를 둘 때에는 부호가 반대인 대칭 곡률을 우선한다.
- 길이 호를 위한 보조 선분은 숨기고, 실제 문제 도형의 실선만 한 번 그린다.
- `curvature`, `lineWidth`, `labelOffset`, `customText`, `labelFontSize`가 프로젝트 저장 후에도 남아 있는지 확인한다.

## 반복 검증

시험 도형 프로젝트를 만든 뒤 다음 명령을 실행한다.

```text
node .agents/skills/mathgraph-drawing/scripts/check-exam-diagram-layout.mjs --strict <project.mathgraph.json>
```

`named-points-too-close`나 `label-offset-too-far`가 함께 나오면 라벨부터 옮기지 말고 점 배치를 다시 설계한다. `top-label-baseline-too-high`는 글자 아래쪽 기준선을 잘못 이해했을 가능성을 뜻한다.
