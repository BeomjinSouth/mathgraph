# 시험 도형 라벨·간격 보정 기준

교사가 직접 고친 MathGraph 프로젝트를 다음 시험 도형 생성에 반영할 때 사용한다. 저장 시각·생성 시각·화면 이동값은 배치 취향으로 단정하지 말고, 점 좌표·라벨 오프셋·가시성·곡률처럼 그림 자체를 바꾼 값만 비교한다.

## 먼저 구분할 것

- 라벨만 어색하면 `labelOffset`을 조정한다.
- 라벨을 2~3글자 높이 이상 멀리 보내야 한다면 점 좌표나 도형 구성을 먼저 고친다.
- 수학적 관계를 나타내기 위한 보조 선분은 계산에 필요해도 화면에서는 `visible:false`로 숨긴다. 같은 위치의 주 도형 선과 보조 선을 겹쳐 그리지 않는다.
- 사용자가 직접 저장한 `labelOffset`과 좌표는 새 자동 배치가 덮어쓰지 않는다.

## point label의 기준선

MathGraph의 점 이름은 `textBaseline='bottom'`으로 그린다. `labelOffset.y`는 글자 중심이 아니라 글자 아래쪽 기준선의 위치다. 따라서 위쪽 이름을 크게 음수로 보내면 글자 높이까지 더해져 꼭짓점에서 과도하게 멀어진다.

글자 크기 27px 안팎에서는 다음 범위부터 검토한다. 이는 초기 후보이며 교사의 확정 위치보다 우선하지 않는다. 전체 수정본에서 위쪽 y값은 -7~8까지 관찰됐다.

| 의도 | 권장 `x` | 권장 `y` | 설명 |
|---|---:|---:|---|
| 점의 위쪽 중앙 | `-10~-5` | `-4~7` | 기준선을 점 가까이에 두면 글자 상자는 위로 올라간다. |
| 점의 아래쪽 중앙 | `-10~-5` | `30~38` | 글자 높이만큼 기준선을 아래로 내린다. |
| 점의 왼쪽 | `-32~-24` | `2~28` | 한 글자 폭과 6~10px 간격을 확보한다. |
| 점의 오른쪽 | `8~16` | `2~28` | 점에서 8px 이상 띄운다. |

도형의 기울기와 주변 선에 따라 범위 안에서 조정하되, 방향 이름만 보고 `y=-20~-30`을 기계적으로 쓰지 않는다.

## 점 간격을 먼저 확보할 것

- 48px 점 간격과 60~80px 연속점 간격은 에이전트가 정한 검토용 경고값이다. 교사가 확정한 최소 간격이나 수학적 제약으로 취급하지 않는다. 글자 크기와 최종 출력 크기에 맞춰 판단한다.
- 두 점이 너무 가까우면 라벨을 멀리 피하는 대신, 자유롭게 정할 수 있는 정의점의 좌표를 옮긴다.
- 문제에서 좌표나 길이를 정확히 지정했다면 기하 조건을 바꾸지 않는다. 이 경우 확대율·글자 크기·별도 지시선 같은 다른 해결책을 검토한다.

P21에서는 D와 P가 약 10px밖에 떨어지지 않아 D 라벨을 100px가량 옮겨야 했다. D를 같은 직선 위의 `(0,1)`로 옮기면 DP가 약 100px로 벌어지고 작은 오프셋만으로 역할이 분명해진다. 이 사례처럼 큰 라벨 이동은 점 간격 오류의 신호로 본다.

## 길이 호

- 길이 치수의 `curvature`는 양수와 음수 모두 의미가 있으므로 부호를 보존한다.
- P17의 대칭 곡률은 해당 예시의 구성이다. 다른 길이·방향의 호에 같은 곡률을 일괄 적용하지 않는다.
- 길이 호를 위한 보조 선분은 숨기고, 실제 문제 도형의 실선만 한 번 그린다.
- `curvature`, `lineWidth`, `labelOffset`, `customText`, `labelFontSize`가 프로젝트 저장 후에도 남아 있는지 확인한다.

## 반복 검증

### 반복 수정에서 확인한 생성 순서

- 보존된 교사 수정본을 최초 시안과 비교한다. 에이전트 보정본은 별도 구분한다. 변경이 없는 항목, 건너뛴 항목, 이동이 막힌 객체를 승인 사례로 세지 않는다.
- 점 이름은 위·아래·옆·교점 내부를 구분한다. 아래 중앙 배치는 P06·P09·P11·P13에서 x=-11~-6, y=30~38이 관찰됐다. 오른쪽 옆 배치는 P06·P11에서 y=17이었다. 아래 중앙용 y값을 모든 아래쪽 꼭짓점에 강제하지 않는다.
- 각도 호와 각도식은 별도로 배치한다. P07~P12의 8개 각도식은 모두 위치가 바뀌었고 호 반지름은 7개에서 유지됐다. 긴 식이나 인접한 두 각은 먼저 글자 상자를 해당 각의 빈 공간에 놓고 어느 호에 속하는지 확인한다. 글자를 옮겼다는 이유로 호를 키우지 않는다. P09의 큰 이동은 혼잡 사례이며 기본 오프셋으로 복제하지 않는다.
- point의 labelOffset은 화면 px, angleDimension/lengthDimension의 labelOffset은 수학 좌표다. 비교할 때 각 파일의 view.scale을 곱해 화면 이동량으로 환산한다. 배율 84%와 fontSize=27은 이 시안 묶음의 조건이며 인쇄 규격으로 고정하지 않는다.
- P13·P15의 곡률 누락은 저장 오류다. 누락을 0 또는 기본값 선호로 해석하지 않는다. P13의 점 크기 4는 점 표식 제거라는 명시적 요구와 충돌하므로 새 기본값의 근거로 쓰지 않는다. P01의 A 좌표 이동은 단일 사례로 남긴다.
- 검사 통과 후에도 실제 글자와 선의 겹침, 각도식의 소속, 출력 크기를 눈으로 확인한다. 현재 검사기는 모든 충돌·보조선 중복·의미적 연결성을 검사하지 않는다.

### 검사 실행

시험 도형 프로젝트를 만든 뒤 다음 명령을 실행한다.

```text
node .agents/skills/mathgraph-drawing/scripts/check-exam-diagram-layout.mjs --strict <project.mathgraph.json>
```

`named-points-too-close`나 `label-offset-too-far`가 함께 나오면 라벨부터 옮기지 말고 점 배치를 다시 설계한다. `top-label-baseline-too-high`는 글자 아래쪽 기준선을 잘못 이해했을 가능성을 뜻한다.

열린 점·닫힌 점이 정의역의 조건인 경우 `--point-marker "객체ID=정의역 끝점"`처럼 해당 점의 수학적 이유를 지정한다. 나머지 점 표식은 계속 검사한다. 거리와 기준선 경고는 위의 검토용 값에 따른 것이므로 실제 선·글자와 수학적 위치를 확인하여 판정하고, 경고를 없애려고 조건이나 사용자 위치를 바꾸지 않는다.

## 100종 반복 검증으로 추가한 생성 경로

새 시험 도형의 GraphA를 만들었으면 프로젝트 루트에서 다음 경로로 실제 글꼴·선·라벨을 검사하고 보정한 파일을 사용한다. 입력은 `operations`와 선택적으로 `view`, `conditions`를 담는다.

```text
node scripts/verify-exam-diagrams.mjs --input 도형.json --output output/새-도형-검수 --strict
```

- `custom-1.graphA.json`은 배치를 보정한 GraphA, `custom-1.mathgraph.json`은 MathGraph에서 열어 편집할 프로젝트, `custom-1.png`는 실제 렌더다. `results.json`의 미해결 항목을 확인한다. 입력·기하 조건을 수정한 경우 이유를 기록하고 다시 검사한다.
- 앱의 AI 생성 경로는 `DiagramQualityEnhancer`에서 같은 `RenderedLabelLayout`을 호출한다. AI가 새로 제안한 오프셋도 보정하며, 문서에 이미 있던 교사 객체와 patch 모드는 보존한다. `PatchApplier.apply`만 직접 호출하는 외부 작성 스크립트는 이 과정을 건너뛴다. 그런 스크립트에는 검사된 `.graphA.json`을 전달한다.
- CLI는 기본적으로 입력의 명시적 `labelOffset`, `labelMathPos`를 고정한다. 새 AI 시안의 제안 위치까지 고치려면 위 명령에 `--generated`를 추가한다. 교사가 직접 고친 파일에는 이 옵션을 쓰지 않는다. 점 위치·호 반지름은 보정 대상이 아니다. 브라우저 없는 Node 환경에서는 실제 글꼴 보정을 실행하지 않으므로 Node 검사 통과만으로 화면 검수를 대신하지 않는다.
- 길이 글자는 해당 호의 끊긴 부분과 연결되어야 한다. 긴 부분 길이와 전체 길이가 같은 쪽에 겹치면 도형을 설계할 때 치수 호의 쪽과 간격을 조정한다. 뒤쪽 면이 아래로 투영된 각기둥도 길이 호가 뒤쪽 모서리와 겹치지 않게 쪽을 고른다. 사용자가 고정한 치수나 기하 조건은 자동으로 뒤집지 않는다.
- 선분 바깥 교점과 둔각삼각형의 외부 수선은 숨긴 **지지 직선**으로 계산하고 필요한 선분만 화면에 표시한다. 범위 밖 교점을 만들려고 선분의 교점 판정 규칙을 바꾸지 않는다.
- 작은 각은 방향각의 경계를 정규화한 뒤 내부 이등분선으로 각도식을 배치한다. 각뿔의 꼭짓점은 원래 점 객체만 표식을 담당하여 검은 점이 중복 표시되지 않게 한다.
- 100종은 에이전트가 만든 회귀 사례다. 교사가 승인한 24종 수정본과 구분하며 새로운 사용자 취향으로 저장하지 않는다. 전체 재검사는 `npm.cmd run verify:exam-diagrams`, 실제 앱의 불러오기·내보내기 검사는 `node scripts/verify-exam-diagrams.mjs --phase app --app-only`로 실행한다.

이 검사는 MathGraph 캔버스와 프로젝트 저장을 확인한다. HWP에 넣을 때에는 기존 `pbj-exam-hwpx`의 수식 실측·13pt/11pt 라벨·68.2mm 출력·실제 한글/PDF 검수를 계속 적용한다. 현재 체크아웃에 `js/utils/HwpDiagram.js`가 없다면 한글 입력 경로를 사용할 수 있다고 주장하지 말고, 한글 입력이 구현된 작업 공간을 확인한다.

## 복합 도형과 함수 넓이

- 같은 각은 동일한 `markerCount`를 가진 두 `angleDimension`으로, 같은 길이는 한 묶음에 동일한 `tickCount`를 가진 `equalLengthMarker`로 나타낸다. 수학적으로 같지 않은 각·선분에 표식만 붙이지 않는다.
- 함수 사이 또는 함수와 수평선 사이의 넓이를 묻는다면 함수와 `functionRegion`을 연결한다. `xMin`과 `xMax`가 실제 교점·지정된 수직 경계인지 확인하고, 축·곡선·음영 전체가 화면 안에 들어오게 배율을 정한다. 함수의 표시 범위 밖, 극점이 포함된 구간, 잘린 음영은 검수 통과로 보지 않는다.
- 복합 사례 검수는 `npm.cmd run verify:complex-exam-diagrams`를 사용한다. 결과의 `output/exam-diagrams-complex/verified/`에 원본 조건, GraphA, 편집 가능한 프로젝트, PNG, 모아보기, 변형 오류 검출 결과가 남는다. 이 검사는 한글 인쇄나 자연어 모델의 모든 응답을 보증하지 않는다.
- 로컬 단일 요청은 `f(x)=…`, 선택적으로 `g(x)=…`, `x=시작값부터 끝값까지`가 분명한 넓이 문제를 함수·음영으로 만든다. 함수 하나만 있으면 `x축`을 경계로 명시해야 한다. 범위가 없거나 정의되지 않는 구간은 추측하지 않는다. 빈 기본 화면의 첫 생성만 영역과 축이 보이도록 확대하며, 기존 화면·교사 객체는 유지한다.
- 로컬 단일 요청의 평면도형은 현재 명시된 `삼각형 ABC`의 `AB=AC`, `∠B=∠C`, `BC` 길이, `∠A` 수치와 `평행사변형 ABCD`의 `AB=CD`, `BC=DA`, `∠A=∠C`, `AB` 길이, `∠A` 수치를 함께 주는 두 형식을 검증했다. 실제 좌표가 조건을 만족하며 점선 길이 호·같은 변과 각의 표식을 한 번에 만든다. 그 밖의 복합 조건이나 자동 배치 범위 밖 수치는 일부만 그려 성공했다고 하지 않고 오류를 낸다. 이는 실제 외부 모델을 통한 임의 문항 원샷 성공을 보증하지 않는다.
- 후속 검수에서 `삼각기둥 ABC-DEF`의 밑변·높이 치수와 `정육면체 ABCD-EFGH`의 모서리 치수를 로컬 한 번 요청으로 만들었다. 각기둥의 뒤쪽 모서리는 `prism`이 투영을 기준으로 점선 처리한다. 높이 `6 cm` 같은 각기둥 치수는 3차원 값의 표기이며, 화면의 비스듬한 투영 길이를 6단위로 맞춘다는 뜻이 아니다.
- `사각뿔 V-ABCD`의 `AB` 길이와 높이가 주어지면 밑면 중심의 화면상 수직 위에 `V`를 두어 높이선의 길이를 요청 수치와 같게 만든다. 밑면 중심 보조점은 숨기고 높이선·치수 호를 점선으로 그린다. 이는 시험용 교과서식 도식이며 3D CAD 모델의 실측 높이를 보증하지 않는다. 첫 시안처럼 비스듬한 높이선이 옆 모서리와 겹치면 수치만 맞았다고 통과시키지 않는다.
- 반지름과 높이가 모두 수치로 주어진 원기둥은 `cylinder`의 가로폭을 지름으로, 두 타원 중심의 세로 간격을 높이로 맞춘다. 원기둥 객체의 전체 높이에는 타원의 위·아래 반높이가 포함되므로 수치 높이를 그대로 `height`에 넣지 않는다. 윗면 중심에서 옆점까지 반지름 실선과 점선 치수 호를, 같은 쪽 윗면·아랫면 사이에는 높이 점선 치수 호를 만들고 뒤쪽 밑면 호는 점선으로 남긴다. 보조 점은 숨기고 치수선의 실제 길이·라벨·저장 왕복을 확인한다.
- 함수 음영과 접선을 한 번에 요청할 때에는 접선의 대상 함수와 색칠 구간 안의 x좌표를 명시해야 한다. 두 함수 중 어느 접선인지 모호하면 추측하지 않는다. 모델이 만든 GraphA도 명시된 같은 변·각 표식, 길이·각도 호, 입체 꼭짓점 이름, 함수 음영·접선의 존재와 일부 연결 대상을 생성 전에 검사한다. 이 검사는 문항의 모든 의미를 완전하게 증명하지 않으므로 실제 그림과 수치 검수를 계속한다.
- 원의 중심·반지름·`∠AOB`가 수치로 명시되고 부채꼴 또는 호를 요청하면 O·A·B를 이름이 보이는 크기 0의 점으로 만든다. 반지름 두 선분과 해당 수치의 점선 길이 호, 실제 중심각과 각도 호를 연결하고, 부채꼴 색칠 또는 별도 호 중 요청한 것만 만든다. 원만 그려 놓고 성공으로 처리하지 않는다. 현재 로컬 원샷은 반지름 1~8cm·중심각 15~165°의 명시 형식을 검증했고, 모호하거나 추가 조건이 있으면 임의로 추측하지 않는다.
- 빈 기본 캔버스에 처음 그리는 원·부채꼴·호만 반지름에 따라 배율을 맞추고 사방 90px 정도의 여백을 둔다. 이미 배율·중심을 조정했거나 객체가 있으면 교사의 화면을 유지한다. 작은 30°와 큰 150°도 실제 앱 PNG, 색칠 안팎 픽셀, 실행 취소·재실행·저장 왕복 및 엄격 배치 검사로 확인했다. 이 수치는 앱 화면용이며 HWP 인쇄 폭의 기준으로 사용하지 않는다.
