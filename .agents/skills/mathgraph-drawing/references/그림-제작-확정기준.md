# 그림 제작 확정 기준

교사가 고친 24종과 이후 길이·각·함수식·같음 표식 검수에서 확정한 기준이다. 새 그림 생성과 기존 그림 수정을 구분해 적용한다. 현재 요청과 교사가 직접 지정한 좌표·위치·크기가 우선한다. 이 문서를 읽었다는 사실이 실행 엔진의 기능 지원이나 최종 검수 통과를 뜻하지 않는다.

## 그리기 전에

- 원문에서 길이·각·같음 묶음·점 이름·숨은선·음영·정의역·끝점·필요한 표식을 정리한다. 조건의 숫자만 맞고 선분이나 각의 소속이 다르면 실패다. 요청하지 않은 풀이 결과나 표식을 더하지 않는다.
- 원문과 좌표의 수학적 관계를 보존한다. 점을 옮겨야 한다면 자유롭게 정할 수 있는 점인지 확인한다. 대칭인 마름모 등은 중심과 대칭축으로 좌표를 계산하고 대응 이름도 정렬한다. 일반 사각형에 임의의 대칭을 강제하지 않는다.
- 평면 길이·각과 입체의 투영 길이·각을 혼동하지 않는다. 각기둥의 대응점은 같은 이동 벡터로 만들고 앞선·숨은선을 구분한다.
- 기존 그림에서는 요청한 부분만 수정한다. 잠금, 점 좌표, 수동 라벨·치수 위치, 크기와 카메라를 자동 배치로 덮어쓰지 않는다.

## 길이·각·글자의 배치

| 대상 | 적용할 기준 |
| --- | --- |
| 길이 | 숫자뿐 아니라 치수 곡선 전체의 방향·휘어짐·글자 틈을 검사한다. 각도 호·숨은선·다른 치수선·점 이름을 피한다. 새 그림은 바깥을 먼저 살피되 고정 이름이 막으면 비어 있는 면을 사용한다. |
| 길이의 소속 | 실제 대상 선분에 연결한다. 정확한 평행 투영의 각기둥에서만 검증한 대응 모서리로 옮길 수 있다. 사용자가 특정 모서리를 지정했거나 위치를 고정했으면 옮기지 않는다. |
| 각도 | 호와 글자 위치를 따로 결정한다. 글자 상자 전체가 해당 내각 안에서 읽히면 화살표를 생략한다. 공간이 부족하면 실제 삼각형·다각형 밖으로 뺀다. 호를 키워야 한다고 단정하거나 다른 꼭짓점의 각으로 바꾸지 않는다. |
| 각도 지시선 | 값에서 자기 각도 호를 향하게 한다. 꼭짓점을 가리키지 않는다. 선 끝에 여백을 두고 화살촉이 선에 비해 너무 작지 않게 한다. 새 앱의 곡선 지시선은 호에서 약 7px를 띄운다. 명시한 항상/숨김 설정과 바깥 배치는 보존한다. |
| 숫자 | 정수는 `40°`, `6cm`처럼 불필요한 `.0` 없이 쓴다. 실제 소수·변수·식은 보존한다. 숫자 접두부가 아니라 전체 식과 단위를 대조한다. |
| 같음 표식 | 연결된 같음 조건은 같은 묶음이며 한 묶음은 한 줄부터 시작한다. 독립 묶음은 줄 수로 구별한다. 표식 크기는 도형에 맞추고 선 굵기 때문에 지나치게 커지거나 작아지지 않게 한다. |
| 함수식 | 함수에 붙은 식과 별도 `y=2` 같은 식을 함께 확인한다. 실제 분수·근호·지수까지 포함한 글자 상자가 선·축·음영 경계·다른 글자·화면 끝과 겹치거나 잘리지 않게 한다. |
| 점 이름 | 글자의 기준선과 전체 상자를 확인한다. 선과 가깝게 놓되 점의 위치와 역할을 혼동하지 않게 한다. 시험용 꼭짓점은 기본적으로 검은 점 없이 이름만 표시한다. 열린/닫힌 끝점은 수학 정보이므로 예외다. |

## 화면용과 인쇄용

- 최신 앱의 새 치수·점 이름·함수식은 명시한 크기 요청이 없으면 24px 이상부터 확인한다. 길이 눈금은 보통 10~16px이며 짧은 변에서는 줄인다. 최종 배율에서 다시 배치한다. 이 값은 모든 그림에 강제할 인쇄 규격이 아니다.
- PBJ 학교 시험지의 한글 그림은 기존 68.2mm 폭, 점 이름 13pt, 길이·각 조건 11pt와 실제 수식 영역 실측을 따른다. 치수선은 최종 인쇄 높이 4~7mm부터 확인한다. 앱의 px를 인쇄 pt/mm로 그대로 옮기지 않는다.
- 한글 출력에서는 수학적 숫자·문자·식·단위를 편집 가능한 한글 수식 개체로 둔다. 라벨을 그림에 구워 넣거나 일반 텍스트로 임의 대체하지 않는다. 실제 HWPX와 PDF를 다시 확인한다.

## 자동 생성과 완료 판단

새 생성은 조건 확인 → 지원 객체 생성 → 최종 크기의 실제 렌더 → 수학 조건과 배치 대조 → 필요한 수정 → 재검사 → 편집 파일과 출력 저장 순서로 확인한다. 직접 PatchApplier만 호출한 결과를 자동 배치 완료라고 하지 않는다. 실제 엔진의 검수·내보내기 경로를 사용한다.

원샷은 사용자 요청 한 번으로 검수된 결과를 받는 것이다. 내부 생성·검토·수정 호출은 따로 센다. 사용자가 겹침을 발견해 재지시했거나 미검수 초안을 직접 반영해야 했다면 원샷 성공으로 세지 않는다. 실패·호출 상한·사용자의 중단을 보존하며 성공할 때까지 무제한 호출하지 않는다.

마지막에는 원문 조건, 실제 객체·좌표, 실제 PNG, 파일 복원과 실행 취소/재실행을 대조한다. 함수는 식·구간·접점·음영 안팎과 열린/닫힌 점의 실제 모양을 확인한다. JSON 형식 적합성과 모델의 통과 판정만으로 수학 조건이나 출력 검수를 대신하지 않는다.

## 근거와 경계

- 교사 수정 24종은 공통 기준의 근거다. 개별 좌표·배율·곡률·큰 오프셋을 모든 그림의 고정값으로 복제하지 않는다. 저장 시각·화면 이동·누락된 곡률·수정이 막힌 객체를 취향으로 해석하지 않는다.
- 100종·복합 45종과 로컬 원샷은 회귀 자료이며 교사 승인이나 모든 문항의 성공률이 아니다.
- 2026-10-06 실제 Astra 6종은 각 사용자 요청 1회·내부 생성/검토 각 1회, 독립 조건 45개가 통과했다. 마지막 선 끝 렌더 수정은 저장된 실제 응답 재생으로 검토/출력 PNG 차이 0을 확인했다. 새 호출과 재생을 구별한다.
- 임의의 모든 문항, 다른 모델, 모바일 그림 가독성, 한글 인쇄와 운영 반영은 각각 별도 증거가 필요하다. 앱에서 검증한 새 필드가 PBJ 고정 엔진에도 있다고 가정하지 않는다. 지원되지 않는 표시를 조용히 버리지 말고 한계를 알린다.

최신 앱의 치수 상세는 `annotation-layout.md`, 공통 도형 검수는 각 엔진의 `exam-diagram-layout.md`, 객체·필드는 현재 엔진의 `feature-manual.json`에서 확인한다. PBJ 한글 출력은 그 스킬의 `통합-런타임-안내.md`와 `exam-export-contract.md`를 추가로 읽는다.
